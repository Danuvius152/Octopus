提交前按可信人类请求确认维护目的与对象。auto 下由主 agent 理解自然语言，/wiki 本身只选择知识来源；询问方法、引用指令或否定维护时只查询。人类明确要求维护知识库且未指定对象时，有界检查当前 Library Markdown 增量，不全库重新整理；指定对象或另有目的时保持该范围。三个形式化日常命令 /wiki maintain、/wiki 维护、/wiki维护 仍等价；带对象或附加正文时按其精确选择限制执行。显式只读控制、父任务限制和当前操作卡始终优先，加载指南不提升权限。

已有文件：已知单文 id/path 用 maintenance_status；日常增量维护多个候选先用 maintenance_select。它只冻结创建时可执行的完整 review；返回的 deferred 是同次观察中已有工作或未核实项，报告原状态，不提交新任务；deferred_truncated 时用 maintenance_status 补缺失项。后续页只续冻结 review，接纳时仍核对当前资格。默认增量不列纯移动；精确 doc 和 links 仍可查当前路径与历史。证据足够直接提交，只有对象歧义或材料缺口才预读正文。只有名称则 compact lookup 定位，重名不猜。按原样 next_cursor 续页；状态元数据不算正文阅读或关联写权。ready=false 不能当作无变化；必要时一次小范围 read/lookup 或 Library limit=1 浏览让索引处理已知变化，再查状态，仍异常就报告，不循环轮询、不重写正文恢复索引。

同身份、同已接受输出版本而仅路径不同，且索引就绪、无来源警告和待恢复尝试，不重新生成题名、Key note、标签或来源，也不为清除 path_changed 制造 no_change。字节未变不能证明直接来源仍有效；来源警告按实际依据复核，不扩大范围。必要的旧名字面链接用 maintenance_status(doc=...,view="links") 有界查看；它包含已 unresolved 的入链，不能用 graph 没看到来断言无断链。已知历史路径匹配不证明问题由本次移动新增，原有出链缺失另算。未被用户选中的关联旧文只读，报告具体修复路径，不借改名扩大范围；历史收据路径保留。

changed 只是版本不同，不证明摘要过时或哪些字段由人新增。冻结页中的 review 按最多三篇一批提交 maintain_batch(selection_id=selection.id,ordinals=[实际序号])，每批独立上下文，共用已读指南和相关材料。服务端从冻结记录逐篇取 review 并在同一接纳事务内核验；任一项失效整次接纳拒绝，执行阶段仍可逐篇成功或失败。新项合批，已有任务复用；selected_items 给出 ordinal/doc/review_key、job_id、reused 及该篇状态，jobs 的进度是完整批次，不能当作某篇结果。retry/cancel 仍作用于整个原 job，重放单篇不自动控制其他成员。

只有单文观察时也可复制原 review 与 review_key：maintain(idempotency_key=review.review_key,paths=[current.path],material="",review=review)。日常目的固定为按用途复核：baseline_receipt_id 为空做首次复核，包括适用的关联比较和已有导航检查；有基线做增量必要复核，阶段逐篇保留。沿用已有适用内容，允许有依据的 no_change，具体检查遵守 worker。幂等键和观察不手造，不混用于其他修订。提交前变化就重新观察；已有进行中或待恢复工作报告原任务，不另排模型，unknown 不冒充已维护。

新材料：将完整原文、已知来源、目标分类和固定幂等键交给 maintain；由框架原样接收并处理去重与排队。是否复用已有文档、发生冲突或实际排队，以真实回执为准；不承诺换键后一定复用。不要为了提交先保存一份。
本次新建文件：以框架记录的新增文件清单为写入范围，保留其中已有正文。相关旧文仅作阅读来源，关联写到新文中。
用户指定的其他旧文修订：只整理明确选择的文件或范围，按该具体目的使用原有固定 key 提交，不混用默认日常 review。无法确定对象、来源或权限时说明缺口，不自行扩大范围。
本入口提交后报告真实排队、复用位置或冲突状态；包括 Weber 自己收到请求，也由框架另开有效 curator worker 整理。同一原请求的任务返回终态后，框架向仍可接收的原会话汇总回传；失败或待确认状态如实保留，接纳汇报不等于汇报已处理，关闭或无法核实的原请求保留卡片与说明。排队前不自行改正文、要点、标签或导航。完成以 worker 实际产物为准。普通保存、小修改和直接新增 MD 只更新索引，不自动总结或再次入库；普通聊天不自动形成材料。

结果返回后先复用已有输出、收据、逐篇结果和索引证据；回传 receipts 已含有界操作及 reason，足以汇报就直接使用，不再导出整份 job。截断、缺失、冲突、失败或需要核对新变化时才定点补证，不默认再做一轮全篇验收。需要任务详情时用 jobs 默认摘要或按固定 key 精确查；完整证据用 view="full", export=true，按路径、字节数和 SHA-256 核对。大 JSON 留文件，短程序只读所需字段。汇报区分原文保全、实际比较与导航处理或不变理由；任务终态及索引 ready 本身不证明知识整合完成。

已知未完成 job 的恢复先核对原状态、实际 item/执行记录和 displayed attempt/vault；证据已足以判断可继续时直接 retry_job，不在提交端抢先通读目标或联网做一遍语义复核。独立 worker 按其当前任务实际取证。真正接纳的重试把未来结果回传归属交给本次入口；旧收据和未确认效果继续用于安全续作，旧会话不自动汇报新一次派发。完成 job 的 retry 只回取原结果；同一控制的原样重放不产生新派发。恢复不扩大原范围，未知效果与未退休的执行仍先按原路径核实。
