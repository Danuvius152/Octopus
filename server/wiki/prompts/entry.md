提交前按可信人类请求确认维护目的与对象。auto 下由主 agent 理解自然语言，/wiki 本身只选择知识来源；询问方法、引用指令或否定维护时只查询。人类明确要求维护知识库且未指定对象时，有界检查当前 Library Markdown 增量，不全库重新整理；指定对象或另有目的时保持该范围。三个形式化日常命令 /wiki maintain、/wiki 维护、/wiki维护 仍等价；带对象或附加正文时按其精确选择限制执行。显式只读控制、父任务限制和当前操作卡始终优先，加载指南不提升权限。

已有文件先用 maintenance_status 取得当前身份、版本、合格维护基线和实际尝试状态；已知 id/path 直接查，只有名称则 compact lookup 定位，重名不猜。按 next_cursor 续页；状态元数据不算已读正文，也不授予关联文件写权。ready=false 不能当作无变化；必要时一次正常的小范围 read/lookup 或 Library limit=1 浏览让索引处理已知变化，再查状态，仍异常就报告，不循环轮询、不重写正文恢复索引。

同身份、同已接受输出版本而仅路径不同，且索引就绪、无来源警告和待恢复尝试，不重新生成题名、Key note、标签或来源，也不为清除 path_changed 制造 no_change。字节未变不能证明直接来源仍有效；来源警告按实际依据复核，不扩大范围。必要的旧名字面链接用 maintenance_status(doc=...,view="links") 有界查看；它包含已 unresolved 的入链，不能用 graph 没看到来断言无断链。已知历史路径匹配不证明问题由本次移动新增，原有出链缺失另算。未被用户选中的关联旧文只读，报告具体修复路径，不借改名扩大范围；历史收据路径保留。

changed 只是版本不同，不证明摘要过时或哪些字段由人新增。先看当前用途的必要依据，入口不先做一轮全篇整理再交 worker 重做。actionable=true 且无待恢复尝试时，默认日常复核复制该项 review 与 review_key：maintain(idempotency_key=review.review_key,paths=[current.path],material="",review=review)。一次 checked 提交只选该文，服务端采用固定的按用途复核目的：review.baseline_receipt_id 为空时由 worker 做首次复核，包括适用的关联比较和已有导航检查；有基线时做增量必要复核。两者均保留已有适用内容并允许有依据的 no_change，具体检查遵守 worker 指南。幂等键和观察不手造，不把它用于其他具体修订目的。提交前变化就重新取得当前依据。已有进行中或录制／索引／冲突待恢复工作先报告原任务，不另排模型；unknown 不冒充已维护或新材料。成功后以实际输出、收据和索引判断；知识整合还须核对实际比较及导航处理或不变理由，旧输入任务成功不等于当前版本完成。

新材料：将完整原文、已知来源、目标分类和固定幂等键交给 maintain；由框架原样接收并处理去重与排队。是否复用已有文档、发生冲突或实际排队，以真实回执为准；不承诺换键后一定复用。不要为了提交先保存一份。
本次新建文件：以框架记录的新增文件清单为写入范围，保留其中已有正文。相关旧文仅作阅读来源，关联写到新文中。
用户指定的其他旧文修订：只整理明确选择的文件或范围，按该具体目的使用原有固定 key 提交，不混用默认日常 review。无法确定对象、来源或权限时说明缺口，不自行扩大范围。
本入口提交后报告真实排队、复用位置或冲突状态；包括 Weber 自己收到请求，也由框架另开有效 curator worker 整理。同一原请求的任务返回终态后，框架向仍可接收的原会话汇总回传；失败或待确认状态如实保留，接纳汇报不等于汇报已处理，关闭或无法核实的原请求保留卡片与说明。排队前不自行改正文、要点、标签或导航。完成以 worker 实际产物为准。普通保存、小修改和直接新增 MD 只更新索引，不自动总结或再次入库；普通聊天不自动形成材料。

任务导航用 jobs 默认摘要，固定 key 用 idempotency_key 精确查。完整证据用 view="full", export=true，按返回路径、字节数和 SHA-256 核对。大 JSON 留文件，以短程序读所需字段，不拼进 shell 参数或环境变量。
