阅读状态重复发布、暖切换的布局成本和图片晚到后的段落漂移仍存在。

## 摘要

展开工具卡后继续阅读，收起时列表变短，浏览器可能把当前位置压到新底部。
旧逻辑可能把这次到底当成用户想继续跟随，下一段输出便把画面拉走。同一时期，
保存子任务会补齐详情字段，外层列表认得原来的卡，内层却可能重新挂载，
让已经展开的内容收起来。

几轮修改各自修掉了一个现象，下一次交互又会触发原判断的例外。滚动调用、
到底通知、会话 ID、行数和 key 各能说明一件事，代码却曾用它们判断首屏可读、
用户还想跟随，或旧操作仍可写入。首次展示一度要追踪 Virtuoso 是否已安装尾行
尺寸。11 月 18 日后半段的修改删掉了这段追踪，改查当前提交的正文末段是否已在
视口内。卡片身份、操作归属和读到的位置各有自己的判断。
[前端异步状态复盘](frontend-async-state-boundaries.md)

## 影响与证据

旧实现和回归构造可以解释几种用户看得见的后果。消息条数未变，Footer 或已有卡片
增高后，最新输出仍可能留在视口外。展开详情或往上翻后，画面仍可能被拉回底部。
切会话时可能先看到按估高排出的画面再校正，或长时间停在准备状态。实时卡转存和
历史前插会打断展开状态或阅读位置。打字和流式增量会牵动内容未变的历史正文。
归档成功后，迟到回执也可能带走用户后来选择的页面。

证据为 Git 差异、合同与回归源码。附件所引的 11 月 18 日性能审查记录了
`08dcda9` 当时的大 ChatView、尺寸检查和归档中间态。后续差异可核对这些路径
如何变化。旧采样仅适用于当时的构建和环境。缺少完整线上故障记录与用户设备的
性能 trace，无法从提交次数推断事故频率。本次未运行产品套件或核验部署。

## 根因与修复

### 1. 浏览器报到底部，被当成用户授予跟随许可

除了收起卡片引起的钳制，旧的到底通知也可能晚于新的上滚输入。按交付顺序更新
跟随状态，会让旧位置覆盖新意图。内层工具输出能消费滚轮，表单能接管按键，
触摸或笔轻点也可能一像素未动。一次输入需要结合其目标、方向和实际位移判断。

当前在点击捕获阶段撤销展开或收起前排队的自动滚动。等测量或下一帧再撤销，
旧操作就可能先写位置。接触暂停与阅读撤销各自结算。主列表有效向下回到底部，
或点 Jump to latest，可以恢复跟随。布局变动和迟到的到底通知只更新几何。
普通上翻的返回按钮叠在正文上，显隐不改变列表高度。视口优先处理阅读与接触，
再处理当前定位，最后处理持续跟随。应用侧只有一个尾部运动和待交付帧，
Virtuoso 仍负责动态行高的正常补偿。
[阅读与跟随合同](../implemented/frontend-transcript-view.md#最新输出跟随与阅读意愿)

### 2. 会话 ID 相同，旧操作就被当成仍有资格

A→B→A 的两次选择可能在 React 提交前结束。只比较最终 ID，看不到第一次打开
已经离开。窗口或 DOM 节点也能在同一次打开里替换，此时旧几何过期，用户仍可能
想留在历史位置。切到管理页再切回同一打开，还需要保留此前的阅读意愿。

当前由 store 的同步通知退休离开的视图，定位与跟随持有原视图和实际 viewport。
写入前后与清理时都复核，旧回调只结算自己的操作。窗口或节点交接只留必要的
身份、锚点和位置。分页的数据接纳仍按原观察、窗口和游标判断。用户改变读位时，
原位置校正失效，仍有效的旧页可以合入。侧栏归档在发起时记录连续前台资格，
离开即失去自动导航资格，成功的归档事实仍然合并。
[视口源码](../../web/src/components/ChatTranscript.tsx)、
[侧栏归档源码](../../web/src/components/SidebarAgents.tsx)

### 3. 详情字段变化触发了卡片内层重挂

`fd7ab9c` 已让外层列表按工作身份识别原生子任务。`MessageDetails` 还用 seq
和 detail_ref 做 key，同一任务从 observed 到 saved 时内层仍会重挂。后来补齐
的 cardId 同样可能变化。按名称或复用的 cardId 合并，又可能把不同工作配成一个。

当前在会话范围内用经校验的 request、attempt、thread 和 turn 认定同一工作，
让列表、包装层和卡片内层连续。详情资源变化后，旧读取独立退出。一次真实卸载
仍会结束该挂载的展开状态。没有变化的投影行保留原对象。文字确实变了，哪怕
key 和高度都相同，首屏也要等当前正文提交。
[卡片合同](../implemented/frontend-transcript-view.md#完成正文与同工作卡连续性)、
[卡片连续性回归](../../web/src/components/MessageBubble.continuity.test.tsx)

历史前插时，几条 child 可能并入同一张卡，行数差无法换算读位。当前在合入旧页前
捕获可见行的稳定 key 与像素偏移，合入后按 DOM 校正。纯实时正文转存时捕获
对应文本起点，匹配持久行后恢复位置，保证范围限于转存前后排版一致的正文。
不显示的根 `thinking` 也在投影时去掉。气泡返回 `null` 仍会留下虚拟行外壳
和间距。原始消息与 seq 继续用于历史窗口和分页。
[分页与转存合同](../implemented/frontend-transcript-view.md#历史分页与阅读锚点)、
[虚拟行间距回归](../../web/e2e/message-spacing.spec.ts)

### 4. 首次展示越来越依赖虚拟列表内部的尺寸进度

早期三次 `LAST` 和后来的重挂列表都能发起定位。当时缺少对第一眼看到的正文和
位置的直接核验。正文读取收口后，必要历史可先于 BG、Research 等辅助数据发布。
数据到达后，React 还要提交正文，浏览器还要布局，页面才有条件揭示首屏。
会话的这几段等待有各自的结束条件。
[会话打开合同](../implemented/frontend-session-observation.md#会话打开与辅助数据)

`e822b20` 已要求尾行实测和尺寸安装。到 `08dcda9`，代码通过 Virtuoso 的
`getState().ranges` 核对实测高度，另外维护 `TailMeasurement`、
`TailInstallation`、`MeasurementBinding` 及重观察的请求和交付。同高度新内容
可能没有新的 resize 通知，回调读到的尺寸快照还可能是旧的。超高 Footer 又会
把持久尾行挤出挂载范围。应用因此要跨 React、
DOM、库的尺寸树和回调顺序，证明中间过程已经走完。

`81b49c2` 改为把 DOM 节点与 React 实际提交的尾行关联，核对当前 Footer
的会话、运行状态、文本与实时项，并检查物理底部和应可见的末段。Footer
独占首屏时，检查其真实末段与已布局的列表空间即可，持久尾行可以在虚拟范围外。
揭示提交时再核一次，期间继续接纳增高。Virtuoso 仍按 48 CSS px 估高并自然测量。
应用通过公开 `scrollTo` 定位，用户可先接管。长卡片只需末段可见。
[首屏合同](../implemented/frontend-transcript-view.md#首次正文呈现)、
[可读性核验源码](../../web/src/components/ChatTranscript.tsx)

### 5. 高频变化唤醒了没有变化的历史正文

以前在大 ChatView 里传递草稿与根流文本。每次增量替换 Footer 组件类型，还会
打断测量。已完成 Markdown 的 source 没变，父组件的无关更新也可能让它重走解析。

当前稳定 Footer 自行订阅当前会话的文本与实时项，提交后通知视口重采样布局。
Composer 订阅草稿正文，外层保留占用、恢复与发送所需事实。Transcript 消费
持久消息、工作快照、当前请求、问题和交互权限。已完成 Markdown 在按 source
做 memo 的叶组件中解析，插件数组保持稳定。控件、归属与权限变化仍能更新。
拆分让状态到达需要它的组件，定位、取消和揭示继续由同一视口协调。
[运行成本合同](../implemented/frontend-transcript-view.md#冷历史与运行成本边界)、
[Markdown 解析回归](../../web/src/components/MessageBubble.rendering.test.tsx)

### 6. 归档写成功后，新画面还没准备好

旧路径先发布归档事实，旧输入区变成只读，然后切到后继重新读取和布局。几个
变化相继出现，可能有刷新感。设备是否绘制了每一帧，需要运行记录。现在归档
仍立即生效，原会话保持可读并尽量维持底栏和正文位置。聊天命令的直接后继须
核对身份和原操作资格。可信空历史可以直接交接，非空历史用预备视图完成可读
核验，再一起切换标题、正文和发送目标。预备失败时保留原会话，已知后继可手动打开。
[归档交接合同](../implemented/frontend-list-reconciliation.md#会话列表与跨重连写入确认)

普通打开已有可信历史时，定位耗尽有效准备时间就退休，沿原列表开放正文与提示，
优先保住可用读位。必要历史缺失或损坏时显示对应的错误和重读入口。超时开放后，
一次新接纳的非空流文本或新生成正文仍可恢复可见跟随。旧重放、快照和布局变化
不触发，真实阅读会撤销资格。恢复沿可见的跟随路径进行，页面不用重新进入隐藏准备。
[超时与呈现回归](../../web/src/components/ChatView.presentation.test.tsx)

## 为什么测试漏检

断言已调用 `scrollTo`，只能看到请求发出。只看最终截图，会丢掉首次揭示到
稳定之间的跳动。固定 mock 高度适合控制帧和回调，但可能绕开字体、真实虚拟
范围、动态 Footer 与浏览器钳制。比较 key、条数或最终 scrollTop，也会漏掉
同高度新内容、重组成卡和行内偏移。用卸载模拟离开则漏掉管理页隐藏和批处理的
A→B→A。同样，行 render 数、Markdown 解析次数和实际绘制时间各回答不同问题。

## 教训与当前边界

- 改动涉及动态高度、身份或异步详情时，先写出用户的具体操作和应看到的结果。
  例如按「展开、收起触发钳制、迟到的到底通知、新输出」复现，再找最早误用的事实。
  单纯样式调整沿用已有阅读和展示约定。
- 同时验证该拒绝和该接纳的交错。上翻后旧运动必须退出，主动回到底部要能继续
  跟随。用户换了读位后该位置校正要退出，仍属有效窗口的旧页要能合入。
- 同一症状再次需要 ready、installed、retry 或 fallback 时，先查当前操作的
  完成条件。用户结果能直接观察时，保留核对内容和几何所需的证据，删掉已被替代
  的证明和写入路径。身份与寿命用受控测试，首屏和读位看浏览器，性能看对应指标。
- 订阅靠近实际消费者。权限撤销要即时执行。正文、控件或提示发生变化时才发布
  对应画面。暖历史与布局复用分别判断，可用性降级也单独验收。

### 当前仍有的缺陷

1. 阅读导航会重复发布相同呈现。`navigate` 调用 `pauseFollowing` 后，
   `publishPresentation(owner, "reading")` 每次新建状态对象，owner、phase
   与可见内容都未变时也会向 React 请求更新。实际 commit 次数取决于 React 调度。
   草稿与流式订阅下沉只减少各自传播到历史行的更新。如要去重，应比较 React
   实际消费的呈现值。同一 owner、phase 下，Dismiss
   可清除 `timeoutHint`，错误和恢复提示也须照常更新。旧审查“100 次输入、
   200 次 commit”的样本来自旧组件树，现版本的提交、布局和绘制成本须重新测量。
   [呈现发布源码](../../web/src/components/ChatTranscript.tsx#L324)
2. 上滚默认动作在捕获之后被取消时，仍可能丢失跟随许可。捕获阶段的 `navigate`
   先暂停跟随，之后发现 `defaultPrevented` 的分支只清理上翻证据。现有浏览器用例
   用监听器制造取消与布局钳制，只断言 Jump to latest 不出现。此时若新输出
   继续增高，可能停在视口之外。普通产品操作中的触发范围还待复现。
   [跟随暂停](../../web/src/components/ChatTranscript.tsx#L591)、
   [取消分支](../../web/src/components/ChatTranscript.tsx#L558)、
   [取消输入回归](../../web/e2e/chat-follow-output.spec.ts#L1137)
3. 切换到已有缓存的另一会话时，正文与列表仍会重新挂载。挂载期间的 Markdown
   memo 不保存跨卸载的解析结果，已有数据仍可能重新解析和量测。当前保留虚拟
   列表自然量测，未复用完整尺寸快照或另设尾部首屏。是否值得缓存或保活，应先
   找出同条件下重复付出的主要成本。
   [正文挂载源码](../../web/src/components/ChatView.tsx#L1315)
4. 长消息中图片晚到可能推移正在读的段落。行身份和整行像素偏移只能稳住行级
   锚点，行内图片没有固定预留空间或独立段落校正。转存前后排版不同也超出
   现有的文本读位保证。
   [资源与读位限制](../implemented/frontend-transcript-view.md#冷历史与运行成本边界)
5. 普通首次定位仍可能超时。两秒只累计有可信基线、正高度、前台可见且没有活动
   接触的准备时间，网络等待另计。主线程阻塞也会影响期限回调。超时让用户能
   继续打开已加载正文，精确位置或可读 DOM 此时仍可能未就绪。若稳定的常规场景
   反复走到这一出口，需要查哪项条件迟迟未满足。
