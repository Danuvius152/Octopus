## 1. Problem Statement

用户已有 Sapphire 的本地资料库，希望各 agent 能准确检索并引用它，Weber 能持续维护来源和主题知识，人能继续阅读和编辑。
过去统一 memory 的注入让无关任务也读取知识库，且低质量总摘要影响答案。用户明确要求仅显式使用知识库时激活。
Octopus 包装了两种 CLI；直接安装原生 skill 不能保证框架中的排队、恢复、委托和应用会话遵守同样的规则。

## 2. Solution

保留 Octopus，增加账户内共享知识能力。沿用 Sapphire 当前 `.data` 中的主库；原始文件是权威内容，索引和提取缓存可重建。
Sapphire 是人的知识工作台；本次完成框架能力和接口，新增界面由用户随后在 app 的 Iterate 中开发。

用户通过 `/wiki <问题>` 查询，通过 `/wiki maintain <材料、文件路径或明确范围>` 入库或维护；另有本次消息查询开关。框架随任务加载小型操作卡、对应指南和工具，普通任务仅保留简短知识能力说明。
各 agent 直接检索和读证据；维护请求交给实际 Weber。新材料的原样接收、保存、持久排队和整理是同一工作流，不另设 `/wiki submit` 用户命令。日常入库仅整理本次新增笔记，可读旧文并将关联写入新文；只有明确指定旧文范围的独立维护任务才能整理既有页面。
已有 Markdown 自身作为来源；需要时新建概念或主题入口，日常入库不自动更新旧概念、导航或反向链接。新增笔记复用 Library 现有分类，没有合适分类则放 Library/Inbox。旧路径保留。

Weber 的实际角色配置在共享接口及维护能力验收后更新，完成真实角色验证后再整理旧库。

## 3. User Stories

1. 作为用户，我希望继续使用 Sapphire 的当前主库，以保留已有资料和阅读路径。
2. 作为用户，我希望保留现有文件名、目录和附件路径，以保持链接稳定。
3. 作为用户，我希望用主题和概念跨目录组织知识，以改善检索而不搬文件。
4. 作为用户，我希望只有显式 `/wiki` 或消息开关激活本地知识，以免无关任务被干扰。
5. 作为用户，我希望下一条普通消息自动关闭本次授权，以避免模式持续生效。
6. 作为用户，我希望已读资料仍在历史中这一事实被正确说明，以理解关闭授权的边界。
7. 作为用户，我希望排队消息各自保存知识意图，以避免忙碌会话串用授权。
8. 作为用户，我希望两种 harness 都遵循同一规则，以便切换后端。
9. 作为用户，我希望当前任务的恢复和必要委托保留授权，以便完成同一任务。
10. 作为用户，我希望报告、文档和 app context 中的关键词不会开启授权，以避免将数据误认为我的指令。
11. 作为普通 agent，我希望直接搜索和读取来源，以避免所有查询都等待 Weber。
12. 作为普通 agent，我希望得到短片段、分页和阅读范围，以控制上下文并继续查证。
13. 作为普通 agent，我希望中文短词、标题、别名和原文都能被检索，以找到相关资料。
14. 作为普通 agent，我希望引用包含文档版本和实际读取的章节或行号，以便复核。
15. 作为普通 agent，我希望识别被替代的结论和过期来源，以避免误用旧决定。
16. 作为普通 agent，我希望明确请求保存时能提交成果和来源，以便 Weber 接手。
17. 作为用户，我希望普通聊天不会自动沉淀，以保留主动选择入库的权利。
18. 作为用户，我希望重复提交不会重复创建维护工作，以避免冗余内容。
19. 作为 Weber，我希望在获授权的维护任务中加载规则和模板，以形成一致的整理流程。
20. 作为 Weber，我希望逐字保留原文并增加有来源的整理内容，以改善文章组织而不改变作者内容。
21. 作为用户，我希望公式、代码、引文和前置字段都保持完整，以免格式调整损坏知识。
22. 作为用户，我希望原文错误和矛盾被另行说明，以保留原始观点和证据。
23. 作为用户，我希望缺失来源被标记待核验，以避免补造事实。
24. 作为用户，我希望来源和概念有明确关系，以追溯综合结论。
25. 作为用户，我希望 Weber 保留一般讨论和思考伙伴能力，以免每次对话都变成知识库维护。
26. 作为用户，我希望有效项目决定、用户立场和原件删除需要明确授权，以保留决定权。
27. 作为用户，我希望日常编辑统一经 Sapphire 或知识接口，以统一版本和冲突处理。
28. 作为用户，我希望并发修改时保留待处理成果，以避免静默覆盖。
29. 作为用户，我希望查看变更并恢复为新版本，以安全撤销整理。
30. 作为用户，我希望维护任务能显示进度、取消、重试和恢复状态，以管理持续工作。
31. 作为用户，我希望其他账户不能访问本库，以保留账户隔离。
32. 作为用户，我希望 app 自己的 token 只访问获绑定的库，以避免扩大授权。
33. 作为用户，我希望本轮 PDF 原件和已有引用被保留，之后明确请求时再单独处理。
34. 作为用户，我希望首轮登记全库清单，并整理普通 Markdown、TXT、HTML 及必要关联图片；工具、临时提取、配套静态文件和 PDF 保留为资产，以明确实际整理范围。
35. 作为用户，我希望文本读取问题明确列出，PDF 的主动排除不被误报成处理失败或已处理完成。
36. 作为用户，我希望视频、源码和配置等保留为资产，以避免未经请求的转写或蒸馏。
37. 作为用户，我希望先完成框架，再获得贴合实际接口的 Sapphire Iterate prompt，以便在 app 中继续开发。
38. 作为用户，我希望入库和整理统一使用 `/wiki maintain`，避免重复学习两个入口。
39. 作为用户，我希望日常入库只整理本次新增笔记，不修改关联旧文，以保持已有内容稳定。
40. 作为用户，我希望普通保存只更新索引并标记整理内容待刷新，明确维护时才改动获准范围。
41. 作为用户，我希望首次旧库整理先看 2–3 篇样稿，确认风格后再批量执行，以校准新增内容。

## 4. Implementation Decisions

### 4.1 职责与存储

- 共享知识模块持有持久数据操作、检索、提取、版本、冲突、访问控制、审计和维护任务；复用现有账户、会话、harness、委托和应用生命周期。
- 主库不迁移，不创建第二份需摘要同步的权威库。来源、概念、入口与整理记录使用可阅读的文档/元数据；全文索引及提取缓存可以从主库重建。
- 引用具有稳定的文档身份、当前物理路径、revision 和定位。不能仅凭模糊标题证明两个来源相同。
- 角色授权绑定已验证账户和配置的 curator agent 身份；显示名称、模型传入的 writer 字段和 prompt 不构成权限。
- 采用用户接受的可信同账户协作，不新增 OS 级写入隔离。服务端接口保证与原生 shell 的能力边界必须准确区分。

### 4.2 显式任务与包装层

- 每条输入携带自己的知识意图，并贯穿队列、逻辑任务、重试、恢复及必要委托；不是会话全局开关。
- 受控工具调用同时验证账户、会话和有效知识任务，任务结束后旧凭据不能继续调用知识接口。
- 常驻只保留简短能力描述；正文、全库目录、统一 memory 和全库摘要均不常驻。
- 查询规则和维护规则按任务分开加载，两种 harness 共用框架的组装点。
- 配置变化覆盖 held process 的复用判断；知识模式不同的中途输入不能沿用已启动进程的旧授权。
- 应用调用、计划任务和委托用结构化意图，正文或数据 context 不授权。已明确提交的材料可以产生获授权的持久维护任务。
- CLI 原生子 agent 必须真实验证工具与授权传播；实现应明确支持路径，不能把原生子 agent 与 Octopus 委托会话视为相同机制。
- 当前的 agent 私有记忆继续独立，不能以此旁路保存和强制加载共享知识摘要。

### 4.3 查询与提取契约

- 查询返回候选标题、身份、类型、片段、版本、来源定位和继续分页信息。当前文本读取支持章节/范围，并明确截断与继续位置；PDF 本轮只保留文件身份、路径和已有引用，不启用全文提取或页级内容读取。
- 检索覆盖中文短词、原文、标题、别名、概念及来源筛选；以真实本库问题验证排名，不将向量库或 embedding 视为必备安装项。
- 文本读取保留原件并记录来源 revision 与读取问题。关联图片保留和定位，不能仅凭文本断言已核验图片内容；本轮不安装或运行 PDF/OCR/视觉处理链。
- 来源发生变化后，相应索引和派生知识需要更新或标记过期；不得静默以旧提取结果引用新原件。
- 来源文档是证据数据；其中的指令不会改变工作流、授权或 agent 配置。
- 默认笔记搜索与模板处理覆盖普通文章、笔记和报告；`Codex Skills/`、临时提取和配套静态资产原样保留，默认不作为普通笔记结果。明确指定或关联阅读可按需读取其文本/图片，PDF 仍不读内容。
- 查询按用户原措辞检索，需要时补别名或浏览目录；Key note/概念/导航只帮助定位，重要判断读取当前正文。全文讨论读完目标文章分页，局部问题读相关章节和上下文；未完整阅读时报告覆盖限制。具体查询及写作指南见 prompt 审阅稿。

### 4.4 受控写入与维护

- 普通 agent 读库和明确提交草稿；Weber 在获授权范围内整理、验证和发布。读取授权不自动成为保存或发布授权。
- 提交具备幂等性、来源和目标范围；队列持久化，失败、取消、恢复与重试均可核查。
- 用户只使用 `/wiki maintain`；框架区分新材料入库、本次新建文件整理和明确范围的旧文维护。没有材料或范围的命令不能默认为全库维护。
- 日常入库绑定本次新增文件清单，服务端校验所有受控写入及发布范围；相关旧文只读，不能改正文、标签、Key note、既有导航/概念页或关联区。新链接写在新文中，反向关联由派生索引展示。重名或重复提交按重复/冲突处理，不能覆盖旧文。
- 新笔记复用 Library 现有分类，无适当分类则保存到 Library/Inbox；后续归类属明确的整理任务，不自动搬迁旧文件。必要的新概念/主题页也须在本次新建范围内。
- 发布检验当前来源 revision 和目标 expected revision；冲突保留成果，重新读取后合并，避免覆盖。
- 原文重构逐字保全原始片段；Key note 优先复用已有要点，没有时才补，不删除原总结。新增内容的 Weber 归属、来源位置与版本由元数据和变更记录保留，开头标题只写 `Key note`。保护代码块、公式、引文、前置字段、别名、嵌入及链接。
- 文件移动不属于本次正文整理。真正需要迁移时，作为另有授权、链接检查的任务执行。
- 历史恢复创建新版本；整理前有覆盖二进制原件的可恢复快照，不能将 Git diff 当作完整备份。
- 完成状态与实际产物和阅读覆盖一致；不能将结构/链接检查称为新增内容语义正确性的证明。
- 2026-10-12 用户放宽内容核验：保护已有总结和核心观点，新增联动按轻量规则处理；不默认对每篇新增内容进行独立模型复核，也不对用户提供的 AI 总结逐句重新考证。Weber 仍检查自己的新增要点没有遗漏、强化或扭转既有观点，并保留原文、链接、版本和冲突检查；结果不得描述为独立语义认证。

### 4.5 Sapphire 兼容边界

- 框架提供 app 可调用的共享知识接口，绑定具体 app 与所属账户；前端和 app 后端使用现有认证机制。
- 现有 Sapphire 的保存、导入、回收站/恢复及 Git 引起的主库修改必须纳入共享版本、冲突、审计与索引更新；不能等新增 UI 完成后才统一写入规则。
- 框架验收须覆盖现有 app 写入的兼容路径，避免两个独立 writer。具体兼容方式由实现核查现有 app 合约后确定，不需要本轮重建 app 界面。
- Sapphire 普通保存更新索引，并标记受影响的 Weber 整理内容待刷新；不自动启动改写。新材料“入库并整理”调用维护工作流，传入本次新增文件清单；针对既有页面的“更新要点与关联”明确限定选中文件，保留用户原文与自写要点。
- 本次只形成 app 增强建议和最终 Iterate prompt。prompt 使用验收后的真实接口、权限、错误与版本语义，不能引用设计中尚不存在的 API。

## 5. Testing Decisions

建议评审以下测试边界；这些是行为验收提案，不是已通过的测试：

1. **共享知识 HTTP 边界**：通过现有请求依赖接入临时账户、主库和数据库。验证读写、分页、来源定位、角色、账户/app 隔离、revision 冲突、原文保全和新版本恢复。优先使用现有 REST 测试方式。
2. **显式消息到工具授权的完整路径**：从 composer/WS 或应用调用进入队列与真实 harness 配置，再调用受控接口。覆盖普通输入、显式输入、忙碌排队、授权变化的 steering、恢复、重试、必要委托、过期凭据和下一条普通输入。
3. **Weber 维护任务的可见行为**：用可控 agent 产物验证统一入口、队列恢复、幂等性、取消、重试、冲突以及逐项完成。验证日常入库中相关旧文可读、不可写，旧文正文/元数据/导航字节不变，重名不覆盖；明确旧文维护则只修改指定范围。再对真实 Weber 做显式查询/维护和普通讨论的验收。
4. **生产旧库整理证据**：核对快照、全库清单、原文逐字保全、既有链接、来源/概念关系、质量问题和最终逐项报告。首次先展示 2–3 篇样稿，用户确认风格后执行普通文本范围；样稿不替代全量清单，工具/tmp/静态/PDF 等排除资产不套模板、不计失败。

仅测外部可观察的保证，不把私有类名、字段名或函数调用顺序当作正确性。
模型输出的语义质量以真实来源和任务评估，不用结构 lint 假装证明总结正确。
无关任务不得新增任何 KB 读取或调用；这是单独的反例验收，不由查询成功间接证明。

代码验收使用项目要求的 backend、frontend、TypeScript 和两个 E2E bucket。用户已明确本次以 Codex 实机验收；Claude 实机部分标为未验证，不能把 skip 算作通过。
框架接口验收在隔离环境完成，再进行实际 Weber 配置与真实库操作。保留现有用户配置和未提交工作。

## 6. Weber 配置与上线依赖

职责和约束在规格阶段确定；实际 agent 配置在接口和维护流程验收后更新。

需要调整现有角色规则中的两项冲突：

- “相关讨论先搜索 vault”改为只在框架显式激活的知识任务中访问。
- “从 private memory 找 vault 路径、用一般文件工具维护”改为采用框架提供的受控知识接口与维护工作流。

保留 Weber 的思考伙伴能力、语言习惯、现有模型/backend/credential、会话和私有记忆。
长期 system prompt 表达智者、读书和思考伙伴职责、概括的表达与总结原则及显式知识触发边界；详细模板、检索步骤、维护写作和发布规则随对应任务加载，主库全文与全库摘要不放进 persona。

实际更新前读取当前 agent 配置并留存可恢复版本，避免覆盖期间的新定制；授权绑定 agent 身份，不依赖名字。
更新后验证普通讨论不读库、显式查询正确引用、维护任务按规则发布且不扩大写入范围。通过后展示首次旧库整理样稿；用户确认样稿风格后才执行批量整理。

## 7. 实施与评审状态

顺序是 **grill → spec / 本地 tickets 评审 → implement → 框架验收 → Weber 配置与真实验证 → 旧库样稿确认 → 约定范围旧库整理 → Sapphire Iterate prompt**。
用户已授权按本地规格和任务拆分实施；框架草案已进入隔离验收。用户随后要求重新访谈，补齐尚未明确的内容整理、提取与角色定制规则。此前已确认的约束继续有效。
本地[任务拆分](local-shared-wiki-ticket-proposal.md)是本次实施依据，未发布到外部 tracker。当前交付状态及尚待决定的分支见[实施交接记录](local-shared-wiki-implementation-handoff.md)。

## 8. Out of Scope

- 更换 Octopus、重写 harness、复制 my-wiki 的 agent/provider/session 平台。
- 安装 uv、切换已登录的 Codex backend、顺带升级 MCP 协议。
- 自动使用知识库、自动沉淀所有聊天、强制统一 memory 或全库总摘要。
- 批量搬迁原文件、改写或删减已有正文、替用户更新有效决定。
- 跨账户或外部 CLI/其他机器共享，新增 OS 级强制隔离。
- 视频转写、独立源码知识蒸馏；Sapphire 的新增界面实现。
- 本轮 PDF 提取、OCR、页图视觉转写、MinerU/Docling 安装及完整 PDF 整理管线。

## 9. Further Notes

所有旧库范围都要进入清单；提取失败项允许明确成为需要处理的状态，不能伪装成整理成功。
生产目录写入和服务操作受环境权限约束，实际执行时遵守工具审批；设计共识不绕过 sandbox。
研究笔记中的统计是只读核查时的快照，首次整理需重新核对当前文件清单。

## 10. What this defers

- Sapphire 新增界面由用户明确选择在 app 的 Iterate 中开发；本次交付真实接口所对应的 prompt。
- 用户 2026-10-12 明确要求 PDF 本轮保留，之后单独处理；未来倾向使用 Codex，具体处理方式需届时明确，本轮不以此阻塞文本知识库交付。
- 视频/源码蒸馏、跨账户/外部机器共享、OS 强制隔离不在已确认范围，需新的明确需求。
- 不预先指定 embedding 服务。只有真实检索评估证明需要且明确部署/数据边界后，才选择额外引擎；当前查询能力和验收不能因此留空。

## 11. 补充访谈的收束

2026-10-11 用户要求先交付当前代码步骤，再通过 `$grill-me` 补齐具体规则。Q17–Q35 和之后的用户补充已确定以下内容，尚不是已完成的生产能力：

- Key note、标签、必要关联与原文保全；既有 Markdown 自身作来源，概念/主题按需要创建，不逐篇复制来源卡。
- PDF 处理分支于 2026-10-12 由用户排除本轮；相关解析器、OCR、视觉和预算不再作为当前实施前置条件。
- Library 现有分类与 Inbox 落点；临时/配套/工具资产按需读取；普通保存只更新索引并标记待刷新。
- 智者/读书/思考伙伴 persona 与简短表达规则、my-wiki 查询方法、Pika 维护写作规则；首次 2–3 篇样稿确认。
- 统一 `/wiki maintain` 入库和维护；日常入库只写本次新增文件，已有笔记只能读取，修改需另有明确范围。
- 放宽后的内容自检、核心观点保全和真实完成定义，保留明确异常报告，避免把结构检查或自检称为独立语义认证。

等待用户最后确认整体共同理解后，恢复已授权实施并按此规格校准现有草案；不启动真实库整理来替代需求确认。
