# 工作视图、可选 Router 与外部 Channel

> **Status:** proposed — 先从原工作事实派生只读视图，再按真实输入来源选择 Router 与 Channel。

当前输入 receipt、命名委派轮次、BG/Research/Wiki 任务各有身份和完成 owner。
跨来源返回已经通过[公共接管合同](../implemented/input-reliability.md#公共返回接管)关联
原来源。待解决的是用户怎样跨会话看见“哪些工作等我、结果在哪里、为什么停下”，
不是再建设一个拥有完成裁决权的 Ledger。

## 第一段：可定位原事实的工作视图

选一个明确的管理问题，从现有记录派生只读工作列表，展示状态依据、原会话、
work/attempt/receipt、问题或结果入口。某条工作已提交、通知待送达、资源仍在
退休可同时成立，页面不得把它们压成错误的单个 done。

列表查询和原记录读取由现有领域 owner 提供。若实测确需持久索引或摘要，说明
它的来源、更新边界、可重建规则与过期展示；索引不得更改原业务结果。前端沿用
[读取与合并合同](../implemented/frontend-list-reconciliation.md)，保全晚到响应、
账户切换、分页和失效目标语义。

## 后续分别激活的范围

**Router / Agent Chat：** 用户确需单入口分派多个工作时，才选择可选 Router。
先定义一个用户请求拆成什么、分给谁、由谁接管问题、怎样定位每个原结果以及
人工覆盖分派。Router 的建议或摘要不成为原任务完成事实，也不重放 unknown。

**一个具体 Channel：** 有明确 GitHub、IM 等来源后，先接一个适配器。定义外部
事件去重键、调用主体与授权、关联原会话、回信目标、重试和人工接管。投递回信
失败沿原身份重试交付，不再次启动已经执行的工作；外部文本和工具结果仍为来源
材料，不能因为经过 Router 就变成系统指令。

账户/工具权限与[接口计划](octo-cli.md)、[协作控制](agent-collaboration-controls.md)
共用原授权语义；Wiki 内容仍经过其受控维护入口。

| 后续候选 | 条件与完成边界 |
| --- | --- |
| Router notes / handover | Router 阶段成立后按实际需要启用。只读线索与新模型输入分开；用户能看见来源和关联理由，提示本身不触发模型轮次，handover 显式选择目标/范围并沿原接纳协议提交。 |
| 语义 Watchdog | 仅在可观测事实不足以发现真实任务偏离、且选择支付模型成本时启用；有限频率/范围，建议或按明确授权行动，保留原工作状态权威，不与运维告警混同。 |
| 官方 Board App / 并发 slot | 先证明视图与授权价值，保留直接本机会话无需 Router 的路径。slot 按真实资源存活/退休计算，官方 App 不获得隐式跨账户权限；争用有实测才增加调度。 |

实体/别名与 Ontology 查询候选归[Wiki 计划](wiki-future-plan.md#实体关系与知识查询的条件范围)，
不因 Router 需要线索再建第二份知识图谱。Channel 选入时补签名/安装归属、thread
映射和显式订阅/停用；不能凭文本相似度推断授权或会话归属。可选 Router 不为
普通直接会话增加模型 hop；性能比较记录 TTFT 与请求成本，按真实证据报告波动。

## 完成条件

- 一个真实跨会话问题能由只读视图回答，并能回到原工作、原问题或原结果核对。
- 队列、等待问题、投递与退休的展示都可由原事实解释；删除/失效后无幽灵任务。
- 若选 Channel，重复事件、断连重试、撤权、跨账户与人工接管均不产生重复工作
  或错发回信；外部指令注入不扩大原权限。
- 派生索引损坏可以重建，且不影响原工作继续完成；验证遵循[测试政策](../testing.md)。
