## 4. 保留的行为与代码接缝

- 查询必须逐消息明确启用。个人事实先定位 `Library/Me`，学籍不能猜补职业；知识术语不因出现“我”转入个人目录。索引只定位，引用读取当前证据；全文从字符偏移 0 按 `next_start` 读至 `null`，版本变化后重取坐标。
- 原文、成稿和核心观点保留；普通保存只更新索引，不重新总结或入库。日常新文维护只写本次新增文件，关联旧文保持只读。已有派生笔记同样不能通过 `publish` 整页替换。
- 只为两篇正文支持的具体强关系补 `[[关联]]`；同目录/宽泛标签不足够。可靠 aliases 与原生 frontmatter 合并使用，不重写原生元数据。
- `store.py`/`search_index.py` 管派生索引和当前读取；身份、ownership、jobs、历史是持久状态，不可用删 DB 的办法重建索引。观测删除后旧身份解除路径绑定，同路径重建不继承旧授权。
- `tasks.py` 在写锁内核验目标、配对阅读页与 assignment 身份；阅读覆盖带 document ID、path、revision。`curation.py`/`links.py` 保全原文、核验新增路径/章节/完整 Markdown 块定位。
- `jobs.py` 的两次重读预算跨重启和手动 retry 保留。持久发表凭证覆盖 prepared/applied/conflict/interrupted；发表状态不明留 attention，不新建模型回合。索引故障不消耗正文重读预算。
- `history.py`/`retention.py`/`app_bridge.py` 管文本 journal、恢复和引用根；GC 前核对当前版本，snapshot tombstone 在列表中立即生效。锁等待/同步 I/O 在线程中，取消后 join writer，取消终态不得被完成覆盖。
- `workflow.py`/`prompts/*.md` 在共同 harness 边界分层加载；权限由代码决定，persona 不授权。`server/routers/wiki.py` 与 MCP/app 网关共享实际合约，Sapphire 新 UI 只在 app Iterate 内开发。

基础提交 `a85582fcc52c53c28193de8aafdd270d452c1980` 只是历史起点。工作树有用户账户、模型、fork、composer 等未提交改动；不要 reset、全量暂存或把无关改动归入 Wiki。本任务未提交这一整份工作树。
