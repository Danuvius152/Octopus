## 1. 目标、依据与文档职责

后续架构工作以**减少仍需维护的行为和事实来源**为目标，不再重新实现已经交付的
SessionOwner、事务、持久输入和 Wiki 恢复。取消旧版本、旧开发接口的支持，同时
在简化中保全当前账户的持久数据。跨机器搬迁以继续使用原账户的 agent、memory、
个人知识库和应用为核心，以账户目录下的持久资料为主体；具体范围按§7.1确认。

**用户确认的优先级（2026-10-23）：** 本轮重点是精简并删除旧接口及其兼容行为。
旧入口退役时连同专属适配、回退、状态和测试一起移除；不以旧客户端、旧测试或过去
支持过为由长期保留双协议。当前客户端和仍使用中的应用同步改用保留入口。保全
当前账户资料是实施约束，不是维持旧行为的理由；换机按已确认范围独立交付，不扩大
为旧版本兼容工程。逐项访谈用于确定最终行为，尚未开始代码实施。

**数据底线已确认：** 当前运行代码能够正常打开并使用的完整数据集，是本次精简及
后续演进的起点。除§6.2 S9 明确授权删除的“已结束且为旧格式的 Wiki 任务历史”外，
内容和归属绝不能因更新减少。删除旧 API 不等于停止数据升级。此前换机时不要求
旧聊天的选择仅限定导出范围，不构成本机删除聊天或其他现有资料的授权。
未来改代码的 agent 须随格式变更交付适配与验证；已确认的存储接口合同见§6.3。

本计划接续[迁移与接口审查](https://github.com/Danuvius152/Octopus/blob/fe2200fbbaa705b99b6a392e188bbb2423b21ae2/docs/review/migration-scope-and-portability-20261023.md)

保留已交付的架构合同及七张暂停票。各处不再维护相互竞争的待办清单。

**核查基线与证据范围：** 本地 `3d793d3`（2026-10-23）及现有文档工作树。初次

## 3. 支持合同与唯一责任

### 3.1 四类操作的边界

| 操作 | 下一轮支持范围 |
| --- | --- |
| 空安装开户 | 安装级 setup 证明仅用于首次开户；并发开户只能有一个首管理员。开户前不运行用户业务，不先造无主默认 agent |
| 当前账户运行与恢复 | 除核验收束后的退役旧请求原始记录及§6.2 S9限定清理外，保留当前账户、历史消息、记忆、文件、密钥和仍需确认的效果；重启不改用户已选择的工具和名称 |
| 基线之前的导入/接管 | 不支持无账户安装接管、旧 memory 布局及任意更早格式；当前实际在用数据必须纳入基线，不能被新代码判为可丢弃的旧库 |
| 从当前基线向前演进 | 未来格式变更须保全已有数据并交付明确的前向升级路径；运行时只保留当前表示，已确认的生命周期接口见§6.3 |
| 跨机器搬迁 | 稳定资料导出成完整包，之后在同版本空数据目标导入；沿当前home布局，可更换home前缀和文件系统，保留业务身份并重建本机绑定。范围与流程见§7，源端无需等待以后导入 |

“当前数据”包括多年前创建、现在仍在使用的记录，也包括当前数据库里沿用旧名称或
编码的事实。以实际运行库确立基线，当前到候选的必要变换和未来格式演进，与基线之前
任意旧版导入分开；未完成无损转换的记录不能先失去读取能力，不可借“只支持当前版本”
清空。取消旧客户端兼容则是明确的接口
收缩：同版前后端同步切换，过期网页需刷新，不保留无限期双协议。

**全票澄清（2026-10-24）：** 用户再次明确，不符合新接口的旧请求原始记录，在
全部核验和必要收束完成后没有保留必要。该规则适用于本计划的所有票，包括已提交
实现；迁移期间原样保护载荷、摘要和身份是阶段约束，不是永久保留义务。核验完成
后清理退役原始记录及专属关联、兼容代码和测试，只保留当前领域仍需的事实，不建
旧请求档案或影子副本。当前正向测试统一最新接口，旧样本仅验证拒绝、有限转换/
清理和中断。核验尚未完成不能删证据冒称成功；本条不按时间清空聊天、知识正文或
用户文件。

### 3.2 合并职责，不合并不同事实

| 责任 | 延续或收敛到的唯一位置 | 可以删什么／必须留下什么 |
| --- | --- | --- |
| 账户与秘密归属 | UserManager、账户 DEK；安装级秘密及 MCP 签名使用 master key | 删 legacy Principal、NULL-owner 业务密钥回退；保留账户撤销/禁用和 connector 当前安装归属检查 |
| 输入与会话控制 | client_submissions + SessionOwner；UI 读 dispatch_state | 删外部裸 WS、旧队列展示和虚假批准接口；实际执行队列投影、quota、DB 锁不按名字删除 |
| Wiki 效果与恢复 | Registry 的准入/生命周期，History 的文件效果，job execution 的原执行引用 | 删旧格式解释及已无责任的补偿；保留原像、receipt、event inbox、outbox、授权/读取证明 |
| 持久格式演进 | 存储模块只拥有当前 DDL/领域表示和等值格式标记；发布负责当次存量转换及核验 | 删除启动历史格式检查和转换层；交接完成后临时转换退出，仍保全当前资料和未来演进能力 |
| 搬迁 | 一个离线模块负责稳定资料导出与暂存导入；CLI为薄入口 | 复用密码、系统路径、存储和身份规则；同一流程内部预检，不新增常驻迁移服务 |

`user_id=None` 在部分数据库查询中表示后台全局扫描，不等于可接受的用户业务身份。
先区分调用者再收紧接口，不全局替换为拒绝。类似地，历史批准消息可保留只读展示，
已提交结果不能因为通知失败变成失败，terminal 也不能证明原 writer 已退休。

## 4. 实施顺序与独立交付单元

本节是本轮简化的唯一实施顺序。每单元完成生产者、消费者、删除项与行为验证后再
交付，不用永久开关让新旧 writer 并行。无需等待暂停的七票，也不以这些单元已完成
为由解除它们的暂停。

| 单元 | 内容及审查来源 | 直接前置 | 交付结果 |
| --- | --- | --- | --- |
| R0：冻结支持基线 | F1、F4，识别运行版本、实际数据库和持久格式 | 无 | 数据/路径/密钥来源清单及候选合同；备份说明已在本次修正，实际盘点待实施时做 |
| R1：收敛当前在线接口 | S1–S3、S5、S7、S10；同步现用生产者；S4 暂留 | R0 中同版协议决定 | 一份队列展示、一条关联控制协议、明确的创建 owner；Wiki 保留现用 HTTP 入口 |
| R2：退出安装时代业务 | F2、F3、F5，联动 S11 | R0 的当前数据与未完成操作核实 | 空库先开户；移除接管、memory handoff、token rotation 及专属日志/入口；启动不覆盖配置 |
| R3：收敛持久格式与账户文件归属 | F4、S6–S9、S11、审查§12.3/§12.7 的文件归属部分 | R0；R2 删除的表/路径应已冻结，避免转换两次 | 当前完整 DDL、一种运行时表示和等值格式标记；发布交接转换核验后退出；附件和长输入统一账户路径；限定清理以外的当前数据无损 |
| 本机发布前资源预检 | Q24、审查§12.6 | 实际 unit、有效配置和现有资源检查职责已核实；可独立于 R1–R4 完成 | 在停止旧服务和消费切换许可前只读检查；失败保持旧服务运行并报告具体资源；不在线认领未知目录 |

## 5. R0/R1：基线与公开协议

### 5.1 基线应证明什么

实施开始时记录实际运行 release、候选提交、配置解析后的 DB/状态/工作根，检查
账户归属、输入状态/投递状态、Wiki schema 与 job item 编码、`off` 存量、旧秘密副本、
`recovered_by` 正向列、external journal 和未完成安装命令。只记录结构、数量及
必要版本，不将秘密或用户正文写入报告。旧报告中的“为0”不能替代这次检查。

区分权威数据和可重建投影：Wiki `index.sqlite3` 内含持久账本，不能按文件名当缓存。
新库 DDL 必须从历史 migration 中提取完整的表、索引、约束和触发器，不能简单删除
`_apply_migrations` 后假定 `_SCHEMA` 已涵盖全部。旧库拒绝应在建表、改 PRAGMA 或
回填之前判定；校验入口不可调用会创建目录、生成密钥或迁移数据的普通初始化。

### 5.2 R1 的具体切换

**S1 最终行为已确认（2026-10-23）：** 排队状态只保留服务器提供的当前完整
`dispatch_state` 表示，删除旧队列协议及前端兼容路径。排队、暂停、恢复及保存结果
失败的状态展示保留；活动状态获取失败、缺失或畸形时明确提示，不能伪装成空队列。
已归档会话仍可正常查看，不因没有活动队列而报错或创建 live Owner。前后端同步
切换，保留 generation/revision 与乱序保护，不兼容旧版队列协议。该决定尚未实施。

**S2 最终行为已确认（2026-10-23）：** 删除当前网页已不依赖的无 ID 发送、中断和
答题 WS 旧分支。当前网页发送已携带 `client_request_id`，中断和回答已通过
`sendCommand` 携带 `client_command_id` 及相应目标身份；输入去重和关联控制沿用
既有实现。仍发送旧包的测试同步改用当前协议，不以测试便利保留旧入口。
缺少必要身份的外部请求明确拒绝，不自动补身份执行；内部 `start_message` 和当前
`resume_dispatch` 保留。用户明确本项只删旧分支，bg/agent 回传积压、结果领取及
调度行为不纳入此次讨论或改动，不再列作待确认分支。该决定尚未实施。

**S3 最终行为已确认（2026-10-23）：** 删除已停用的旧工具批准／拒绝链，包括
`PendingApproval` 类型及导出、恒定失败的 `approve_tool/deny_tool`、专属 WS／回执
分支、旧操作标签与只验证该兼容行为的测试。旧动作统一按不支持的操作拒绝。
当前问答的创建、完整回答和取消继续正常工作，已有历史批准记录仍可读取展示；
不改已有 agent 的工具配置或当前权限设置，不重新启用另一套工具审批。该决定尚未实施。

**S4 本轮暂留（2026-10-23）：** 用户要求“有用的话不删”。复核发现 stdio 分支
由缺少 `session_id` 触发，并非 HTTP 连接失败后的自动接管。当前正式会话走 HTTP；
旧形状仍被参数装配检查使用，工具模块也保留 `python -m` 单独启动及环境配置的
诊断入口。不能将“没有生产调用”直接写成“没有用途”，本轮先移出删除范围，保留
现有诊断能力。此处依据源码和现有测试调用，不宣称已实际验证每个诊断入口在当前
账户配置下均可用。保留诊断用途不恢复 F3/F5 已取消的无账户业务和安装 token 授权；
诊断仍遵守当前账户及工具授权规则，不将其扩建为 HTTP 故障切换机制。

**S5 最终行为已确认（2026-10-23）：** 新建会话和定时任务必须有明确的所属 agent。
全局创建接口要求 `agent_id`；agent-scoped 路由直接使用 URL 中的 agent，页面自动
携带相应身份。删除缺省查找 Default agent，以及全局 schedule 创建用 `session_id`
替代 agent 归属的旧格式和专属兼容测试。缺归属或归属不属于当前账户时不创建资源。
当前 MCP session-scoped schedule 从已验证的会话确定所属 agent，其授权与目标会话

### 7.1 接口和数据边界

一个离线模块提供真正可调用的**导出、导入**两个操作，CLI为薄入口，必要预检
在操作内部完成。导出一个固定时点的完整压缩包，同版本空目标可独立导入，
源机器无需在线。用户当前只要求接口实现与隔离验证，不要求生产实际搬迁。

| 类别 | 范围 |
| --- | --- |
| 账户与agent | 原账户ID、用户名、密码校验材料、所需密钥/DEK；agent全部自定义配置、归属与凭据关联，登录后直接使用，不重新认领或补默认配置 |
| 账户文件 | memory、普通workspace文件、附件、研究资料、应用代码/配置/.data及必要数据库关系；可重建运行依赖在目标重装 |
| Wiki | 实际知识正文、来源材料/证明、内容历史、业务身份与查询/维护所需的当前业务事实；不能把数据库整体当缓存丢弃，也不把必要依赖扩大为所有旧任务原始记录必搬 |
| API配置（Q22） | 账户保存的API地址、密钥和关联保持；CLI订阅登录token/refresh token/认证缓存无论存于文件或数据库均排除，在目标重新授权，不静默换其他凭据 |
| 排除（Q21等） | 旧聊天、原生线程/transcript/resume、为历史会话额外收集的外部/fork工作树、运行进程/PID/socket/lease；全部周期/一次性任务定义、启用配置和待触发状态 |

账户目录是文件主体，主库记录、密钥和实际Wiki注册也须按真实依赖收集；
不能只压缩文件夹或把原主库整库入包。所保留知识依赖的来源与效果事实仍完整，
不恢复可执行旧工作。源端聊天、任务、登录及文件不因导出被删除或改配置。

### 7.2 目录与稳定导出

目录按用户所说“就按现在的吧，比如/home/jack”：沿用当前home内布局，换home时
只替换对应前缀及系统定义的路径字段，不要求用户逐项配置任意分散目录。
空目标指本次使用的Octopus数据位置没有既有资料，不要求整个home为空。
实际所选根的重叠部分只收集一次，不支持的必需布局或外链明确报错，不静默漏收。
本机现有Wiki位于账户的应用.data内，状态位于同一账户的wiki目录，无需额外设计
任意外部根的分发流程；其他安装不能直接套用这一现场事实。

导出工具等待当前任务自然收束，暂停相关写入并确认外部writer停止，取得数据库
与文件的稳定副本后恢复源端；压缩与传输从副本进行。复用现有停启和writer退役
能力，不新建常驻迁移状态机。单库一致性不替代跨文件与数据库的一致副本。

用户本轮确认“稳定后导出”：会影响所选资料一致性的未决写入报具体阻塞原因，
交原责任模块处理后重试；不把未决执行过程带到目标继续恢复，不伪造成功或删除
不明效果证据，也不要求所有历史任务都成功。包只代表导出时点，不提供后续同步。

### 7.3 导入、失败与验收

包包含版本、相对条目、完整性摘要和必要恢复信息。导入先只读校验版本、完整性、
密钥、路径边界与空数据目标，再在私有暂存区恢复。由现有责任模块重建安装、
Wiki注册、observer和文件身份等本机绑定；只调整系统管理路径和明确已知配置，
不改用户prompt、知识正文或任意第三方代码，不自动扩大访问根。

所有资料及配置验证、持久化完成后才启用。损坏/缺失内容、错误密钥、越界条目、
非空目标和I/O失败明确报错，不破坏既有资料，不半启动。中断后只清理本次拥有的
暂存/未启用产物，再重新导入；不做断点续传。即使目录同在home下，也不能声称
全部写入天然原子，暂存和启用边界须实际验证。

19负责核心资料及公共流程，20接入Wiki，21接入应用，22交付完整入口和一次完整
隔离往返验收。分项共用实现与失败处理，不制造临时入口或切片支持状态；公共检查
与模型调用复用有效证据，不各跑一套。最终证明原账户登录、配置与字节保全、
知识查询/来源及维护正常、应用重装依赖后读写原数据；原agent的新会话在预期凭据
完成必要重新授权后验证memory/Wiki。迁移不恢复源端任务，也不自动清理源数据。
