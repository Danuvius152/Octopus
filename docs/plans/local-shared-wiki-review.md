## Standards

两项 P1、一项 P2，均补可复现回归：

1. **章节重排冲突的 JSON 可能覆盖原文。** 原实现把重排参数当作冲突正文，恢复 after 可写回 Markdown。现在统一原子记录 `proposed_operation`，历史不展示它为正文候选，拒绝直接恢复 after；修改当前正文后提交旧布局、查看历史、尝试恢复的测试证明原文保持不变。
2. **入库 worker 在事件循环等待文件锁，可能和 Sapphire Git 互等。** 同步读取、写入、SQLite 和重试移到线程；取消时等待线程完成。入库在拿到锁后重新检查取消状态，队列取任务使用原子 claim。真实文件锁竞争测试让异步应用监督释放锁，验证事件循环继续执行；另一用例在等待锁期间取消，验证不会创建文件。修复前两个回归均失败，修复后通过。

3. **取消终态被后续 worker 状态覆盖。** 完成、失败和其他 worker 更新现在以 `status=running` 为条件原子写入；取消本身也用数据库原子条件保护已完成任务。受控交错测试暂停完成/失败写入，先返回 cancelled，再释放 worker，确认最终仍为 cancelled。修复前两例失败、修复后通过。

没有额外阻止交付的 Fowler 启发式问题。审查只评价规范与正确性，不代替业务验收。

## Spec

三项 P2，均补可复现回归：

1. **改名丢失文档身份及 Weber 整理归属。** 增加独立身份 ledger，保留已有 ID；真实 inode 移动及应用 journal 中唯一的相同内容移动迁移身份和 ownership，来源显示当前路径。外部变更恢复使用同一迁移逻辑，变更历史保留前后 ownership。改名后刷新整理区及提取缓存重建的测试证明 ID 不变、来源仍可定位、原文可完整恢复、Key note 不重复。无法可靠认定的移动不猜身份；缺少可信 ownership 的生成区保留为冲突，不当原文重复整理。
2. **关联说明与章节补充中的新增链接未校验。** 现在检查所有新增整理区及重排补充链接；保留原文中的旧坏链。关联说明和新增章节各有拒绝坏链接、原文不变的回归。

3. **来源 ID 缺失时错误回退旧路径。** 有稳定 ID 的引用严格按 ID 查询；来源移动后删除，即使旧路径出现相同内容的新文件，原引用仍标记过期。inode 移动核对还包含修改时间，以避免正常 inode 重用偷换身份。包含检索刷新、同内容新身份和过期检测的回归，修复前失败、修复后通过。

显式授权、普通消息关闭授权、实际 curator 身份、日常只写新增文件、原文保全、PDF 排除及按任务加载的检索/风格规则，独立 Spec reviewer 未发现其他明确偏差。Q35 样稿确认是用户已经选择的发布前步骤，不是框架实现遗漏。
