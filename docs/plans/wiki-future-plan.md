## 2. 产品职责和实施依赖

- **Octopus/Wiki 核心**拥有账户/主库身份、查询和引用、受控维护、历史/恢复、持久任务与索引。App 不各建索引、LLM runner、维护队列或另一份权威正文。
- **Sapphire**负责库目录、搜索/标签、文章预览和直接文件编辑、附件、Git、草稿冲突及版本体验。保留现有多库和手机交互，不接管所有精读聊天。
- **SmartReader**负责围绕当前材料解释、比较、质疑、研究讨论、引用回跳和 reader 草稿；用户选定有价值结果后才进入主库。保留材料×agent 会话关联、摘录、PDF 和下载能力，不锁死用户的 agent 选择。
- **Weber**仍是思考伙伴及绑定 curator；普通对话、reader 写作和获准 Wiki worker 是不同执行范围。只读或提交维护都不赋予直接发布权。

建议的依赖顺序：

| 阶段 | 完整交付 | 依赖/完成条件 |
| --- | --- | --- |
| A | 共享引用/能力与受限 client 授权 | 先核当前 owner 及 App；新增授权同时覆盖直接网关、AppAgent、核心 REST/MCP 与撤权，不启用半条绕过路径。 |
| B | Sapphire 共享搜索、紧凑卡、标签列表/筛选 | 所用 server capability 已实现；保留离线/非主库模式，真实浏览器验证无串库。 |
| C | Sapphire 来源/反链/任务状态、SmartReader 引用阅读 | doc/revision/selector 和解析一致；未安装阅读器时仍能原位预览。 |
| D | SmartReader 按需材料与可继续全文阅读 | 浏览器-only 和 Wiki-bound 都实际可达；局部问题不重传全文，整篇任务仍读完整。 |
| E | reader 草稿与明确入库/专题修订 | 保存有版本/回执；一次提交一个 durable job，来源及目标明确，无重复创建。 |

按实际启动范围拆成功能完整的纵向交付，不为了应用先重做核心迁移。Sapphire 只接现有获准 owner 功能时可先推进；跨 App 能力必须先完成相应授权闭环。本文不启动这些开发或授权写入。

## 3. 多 App 授权：保留 owner，增加受限客户端

旧设计提出 `client_apps=[{app_id, permissions:[read, submit_maintenance]}]`，这是待实现合同，不是当前配置字段。保留 `config.app_id` 作为既有 owner/provider 及 app_bridge 归属，不能把它改成 SmartReader 来绕过限制。先核实际账户、Vault、owner、App id 和 root；名称和 URL slug 不作为身份依据。

| 权限 | 可以开放的最小能力 | 不因此开放 |
| --- | --- | --- |
| read | 获准文档发现、读取、引用、局部图及相应 read 任务 | PUT document、publish、organize、restore、配置、快照管理；不能把全部 GET 默认视为安全。 |
| submit_maintenance | 在授权范围提交具体材料/目标，查看本客户端任务；若需要取消/重试按 job 归属校验 | 阅读 agent 自己发布正文，或操作其他 App/账户的 job。 |

端点白名单由一个共享策略函数实施，普通账户 agent 的常驻查询与 App 受限客户端策略分清。无新 client policy 的既有配置保持兼容；新增字段有 schema、配置代/缓存失效和迁移语义，不能只在前端藏按钮。

相同策略覆盖：`/apps/{id}/wiki/*`、App `agent/chat`/`ask`、用户真实 `/wiki` 入口及后续受限工具调用。可信 `session.app_id` 及任务 provenance 进入核心授权；MCP 调普通 `/api/wiki/*` 时不能绕过 client 权限，也不能从材料 context 中信任浏览器声称的 app id/路径。

撤权阻止新的请求和后续受限调用；已接管 durable job 按其实际授权及取消语义处理，不默删任务或伪造回滚。绑定 Weber worker 继续依靠 job assignment，不能直接继承 reader 的普通写权。列出越权、跨账户、撤权后续轮、手写命令和不同入口一致性的负向回归。

## 4. Sapphire：保留体验，接通共享能力

### 搜索、目录和标签

普通搜索、标签点击不调用模型。只有显示库与 Wiki 绑定身份一致时使用共享检索；切到另一个库保留本地阅读/搜索并如实标识，不静默拿主库回答。standalone/localStorage 模式保持自身语义，不假装具有同样的索引、来源或维护能力。

共享请求使用相对应用根的 `wiki/...`，Sapphire 自己的文件服务仍是其 `api/...`，不要混成 `api/wiki`。沿用同源认证或既有 App bearer，不在页面/分享链接中写 token。初始化和绑定配置代变化时核 capability，不每个按键请求 info。

卡片显示题名、必要路径差异、一句 description、命中章节/片段、类型和必要来源状态；不把 BM25 分数、模型供应商、内部 JSON 放进普通产品流程。重名展示路径，不按首个 basename 匹配。空/部分结果、索引更新中、身份删除分别表达，不用搜索失败自动生成一篇文章填库。

待新增统一标签合同：search/documents 使用 `tags: string[]`、`tag_match: all|any`（默认 all），标签面板读 tags 列表；HTTP 用重复 query 参数。无关键词同样支持过滤；先目录/角色/标签过滤再排名分页，cursor 绑定相同过滤和索引代。facet 按完整匹配集合的不同 doc id 计“文档数”，不因章节重复计数，不冒充独立来源数。保留显示原文，服务端统一匹配规范化；第一版不引入复杂层级/聚类/全库标签清洗。

宽主题分组要以当前有实际材料的方向为依据，同时用当前索引补旧导航未收录文；同源摘要不制造虚假共识。小库不为形式创建庞大分类树或虚拟文件树，分页/目录懒加载由实际成本触发。

### 阅读、保存、维护与版本

Key note、正文、关联与来源分区可辨，元数据默认不干扰正常阅读。generated 是整理归属，stable 不是事实核验徽章。来源缺失、变化或解释待复核分别展示，不能为了界面全绿补造论文/verified。

出链/反链从共享增量索引按局部邻接范围加载，不打开每篇就扫描全库、不向旧文写回反链。当前版本和引用定位保持一致；旧路径 link unresolved 与本次改名因果分开。跳 SmartReader 传真实 vault/doc/revision/selector，不能复制整篇正文、token 或任意文件读取权限；未安装或未获准时继续现有预览。

普通保存只走一个 writer：沿用现有 save/app_bridge，或明确迁到 Wiki document API，不能同一次保存两边各写一次。用户小修保留现有整理状态，只表达真实摘要依据漂移；不自动触发 Weber。草稿、回收站、Git、附件、公式、PDF 人工阅读和移动端保持。

新材料直接提交完整原文一次；已有/刚创建文件用实际路径及需要的真实创建回执。当前 UI 不提供 change_id 时须从合法历史/桥接取得，不能编造 created_changes，也不能让创建失败退成全库维护。旧文由明确选择范围提交，相关页不自动勾选。

任务页分清排队、处理中、已发表、索引待恢复、attention/失败、复用及取消；索引恢复不叫“重新生成文章”。历史恢复入口只对实际可恢复版本开放，失效/退役状态如实显示，不创建日常整库快照。

验收覆盖：标签 all/any/目录交集/counts/分页、同名歧义、移动/旧版本、跨库晚到响应、请求取消、保存冲突、一次写入、手机/PDF/Git/阅读位置。现有 debounce、query ticket、open epoch 等保护不能因替换搜索实现被丢掉。

## 5. SmartReader：材料、对话、引用和写作

### 三种材料身份

| 材料 | 权威与读取方式 |
| --- | --- |
| 浏览器-only | reader UUID 和浏览器正文；模型只见实际提供范围，UUID 本身不让 Wiki 能读全文。 |
| reader capture/draft | App 数据内的受限 handle、revision 和生命周期；不是任意 URL/绝对路径的读取授权。 |
| Wiki-bound | 已验证 vault id、服务 doc id、revision 和 selector；reader UUID 继续作为 UI 自身身份，路径只是显示/定位线索。 |

外部网页和库文同名只产生候选，不自动绑定。旧缓存标明快照，不冒充当前主库。服务确认绑定后才提供读能力，删除后的同路径新文件不能继承旧引用。

### 避免反复全文注入，仍可完整读文

旧附件审阅发现 `readingContext` 每轮最多附 150k JS 字符串单位正文，选区另最多12k；这是历史源码观察，开发前重新核当前 App，不直接当成当前线上测量。目标是按需要可达，而不是换一个固定截断数字。

- Wiki-bound 局部问题附材料身份、当前选区/quote 和问题，由 agent 读必要上下文；不重复整篇传输。
- 浏览器-only 局部问题提供真实选区及附近内容；全文分析须按同一材料 revision 连续提供到末尾，不能只传 UUID 或前半篇。
- 高频多轮精读需要时实现 reader capture/read：handle 受账户、App、conversation/task 和版本约束，存于 App data，带保留/删除语义，不进入 Wiki 默认索引。
- 每轮只提供用户新问题、目标身份/版本、本轮新增范围和必要状态；同一材料继续同一会话。历史压缩后需要证据再取读，不能承诺永久记忆。
- 引用版本变化使旧坐标失效，重新定位；没有实际 capability 时不能在 prompt 中调用不存在的全文工具。

验收保留连续三轮 payload、实际读取覆盖、模型 usage 和回答质量。payload 变小不等于全局输入 token 同比例下降，不能牺牲完整阅读换成绩。

### 引用与坐标

引用绑定 doc/revision 和真实 heading/block/range，必要时保留 exact quote、prefix/suffix；不要让 quote 的首次 `indexOf` 成为精确定位的最终判断。重复句、重复标题、块锚点、中文、emoji、公式、链接和去掉 frontmatter 的显示偏移都需处理。

Wiki 提取文本坐标为 Unicode code point；浏览器 DOM/String.slice 是 UTF-16；raw 源文件又是另一套位置。Markdown block/heading 到 DOM 有明确映射，不能只给字段改名。PDF 使用页面和文字层范围，不套 Markdown offset；版本不符时重新定位，仍歧义就显示候选/章节，不能高亮一个貌似正确的位置。

跨 App 导航由实际获准的 SmartReader id 解析，不硬编码 slug；URL 只带必要引用参数或 opaque ref，不放正文/凭据/私密会话。跳转可用不等于目标已获读取权限。

### 草稿、讨论和主库维护

解释、质疑和研究发散可停留在对话，不固定加载 writing 或自动生成知识页。用户明确写作时复用共享表达规则，区分作者、用户假设与 Weber 推断，不把讨论产物伪装成外部原文。

reader draft 若实现文件保存，必须有身份、revision、保存/编辑 API、真实回执、UI 展示/下载及冲突保全，放在 `.data`，rebuild 后仍存在。对话里写出文字不等于草稿已存；草稿保存不提升 Wiki 权限。现有 App 对话工作目录机制不能代替完整草稿 UI/API。

明确入库/修改指定专题后，提交实际选中的材料或 draft revision、真实来源、目标和稳定幂等键；同一点击/SSE 重连不造多个 job。已有文用当前版本定点维护，新文不先保存再重复创建。已授权同范围继续执行，不固定“生成→再次审批→重新授权”；对象或冲突确有歧义才澄清。

发布与索引完成后才绑定真实 Wiki 产物。页面关闭、停止接收 SSE 和取消 durable job 是不同动作；消费事件按本请求 request id，不能收同会话下一轮终态就宣称本次完成。

## 6. 检索、知识积累和条件性优化

先提升真实内容的 description、角色、可靠别名、必要主题关系和适用综合，再决定是否加技术。优先记录稳定且有复现的缺口：原词/别名失败、主题方向漏召回、模板噪声、重复摘要挤占、来源层级误用，分别诊断候选、阅读充分性和答案。

有独立用途才维护 Topic/Concept/Synthesis 或相关专题中的问题/分歧。已形成的解释可直接复用，缺必要细节才追来源；不追求页数/关联数，不把摘要循环摘要当长期学习。评价首次整理＋后续维护＋多次查询＋人工纠错的总成本，而不只看索引耗时。

若触发 V2-07：固定语料/模型/问题、先有词法基线，比较 exact/alias、中文跨表达、宽主题/多方覆盖、来源重复和答案条件；保留未参与设计材料。检索 Recall/MRR/coverage、实际已读依据、答案支持率/confidence、P50/P95、冷热 IO、token/缓存/重试分别记录，首次 search 未命中不直接等于最终任务失败。

语义/QMD 只作可选 adapter，持久业务身份/历史不交给向量索引。固定 backend/embedding/chunk fingerprint，变化只重建派生索引；失败有词法降级和明确新鲜度。融合职责只选一处，不无理由重复扩写、RRF 和重排；原始分数不直接加成事实可信度。lookup 不绕入模型重排。QMD 旧 v2.8.3/main 接口研究只作历史参考，实际采用前核当时版本及官方参数，不把旧 Unreleased 断言当现况。

中文规则保留技术字段原语言，不常驻两份同义双语。语言对照仅在明确质量/成本缺口时做同义、同配置、同材料的少量试验，不默认新增18次模型调用；不同 tokenizer 的一般研究不能预设本项目英文更省。

自然知识评测继续 opt-in，与确定性发布检查分开；固定个人事实 gold、已读缺口与保全指令若互相矛盾，应保留失败并修正下一轮设计，不能改预期追认。无需为了每次发布重跑已经接受的内容和旧付费问答。

## 7. 共享写作、其他 App 与协议演进

现有 Wiki worker 能按需加载 article/writing。全局或 App 写作自动装配仍是后续能力：从真实写作意图选择共享规则，不因出现“文章/总结”字样就触发；不另跑一个 LLM 分类器。不新建多套相近指南，不让写作模块授予工具权限。

新结构化 task/context、引用或 capture 字段须贯通 Pydantic、HTTP/App transport、MCP 可见工具、权限校验、生成前端合同和实际 UI。以服务器事实声明 capability，未上线能力保持关闭；旧客户端兼容和撤权/取消/重连一起验收。

其他阅读、研究或计算 App 后续按同一受限 client/引用/任务合同接入，先明确具体用户行为和价值，不为“未来可能”建立通用编排系统。新增 Wolfram/计算、网页抓取或其他连接器不从这份文档自动获得开发、联网或主库写入授权。

## 8. 保留的框架待办和运维约束

**R06（条件恢复）：** Claude session 从 Codex agent 继承 reasoning/tier 时，按实际 backend 和字段来源处理：不消费的继承值不参加校验，明确给不支持 backend 提交非空值仍拒绝；省略保持绑定、null 恢复继承，不能清掉 agent 默认或丢 transcript 来绕开。覆盖跨 backend/credential、会话 override、归档/运行中修改、持久化与 preflight 一致性。恢复开发前先核当前代码和 provider 可用性，不复用旧缺陷结论。

**R14（不自动恢复）：** 保持用户已选择的自动索引策略。若未来明确恢复性能调查，再区分冷启动、无变化补偿、单文增删改、查询、关闭等待与注册 vault 数量，记录 IO、观察器、索引代际及并发 API/WS 延迟。每个当前注册库保留当前 Store 并持续接收事件，不再按 32 个 Store 淘汰；单 Store 的原始坐标缓存仍有上限。当前线程等待不能因超时包装被当作已停止。多账户测量、旧索引是否继续服务均需实际需求/产品决定，不借本次文档整理启动。

**发布基础设施：** 继续复用已审查的准备/排空/切换流程。源码回退不覆盖新数据，不为文档更改重启；共享依赖/配置的影响如实记录。临时认证出票前的锁失败保留，scope 不写进文件/后台；实际模型链的临时票据 finally 撤销。若以后将私有操作脚本产品化，先有明确复用价值，再做公共接口/恢复/回归，不复制更多一次性部署框架。

## 10. What this defers

- PDF 自动提取/理解、HTML 新材料转换入库和任意 HTML 原源码定点改写；人工预览保留，格式/源坐标需独立合同。
- 完整来源根闭包、深层依赖传播、自动独立证据计数、全库语义矛盾扫描；先满足真实出处、已知直接关系和局部复核。
- 未被证实需要的向量/重排、全库自动聚类、每段QA生成、庞大主题树和通用图数据库。
- 多 Wiki 主库注册模型、复杂跨设备协作、OS级 App sandbox；现有同账户/受限 client 不冒充这些能力。
- 被用户明确停止的额外多账户压力测试、旧材料重跑、固定语言大实验和额外兼容回退构建；仅在用户明确恢复相应范围后再启动，发现新缺口只提出分析或恢复建议。
- 日常全库备份、每次保存自动Git提交/推送、批量删除原件或历史；本文不授权任何实际主库清理。

暂缓项不被写作已实现，也不作为当前核心失败。未来计划的排序和范围随实际使用更新，不再保留一份互相矛盾的复制任务 prompt。
