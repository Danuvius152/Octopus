状态：Q1–Q36 的框架工作已实施、部署并完成 Codex 验收，实际 Weber 已更新；T6 首次旧库批量整理等待 Q35 样稿确认。未发布到外部 tracker。详见[实施交接](local-shared-wiki-implementation-handoff.md)。

## 01 — 显式查询与任务授权

**Blocked by:** 无。

**What it delivers:** 同账户 agent 经 `/wiki` 或消息开关搜索并读取 Markdown 原文、准确引用；普通任务不读库。路径覆盖 UI、队列、两种 harness、MCP、服务及隔离验收。

- 显式意图逐消息保存；排队、模式变化的 steering、恢复/重试和必要委托正确传递。
- 工具校验账户、会话和有效任务；过期授权不可重放，下一条普通消息关闭新访问。
- 搜索/读取有分页、范围、revision、精确引用；中文短词、标题和别名有实际行为测试。
- 不注入全库目录、摘要或正文，保留 agent 私有记忆的独立性。
- 两个 harness 共用组装规则并完成隔离验证；用户指定 Codex 实机验收，Claude 实机明确标为未验证。CLI 原生子 agent 与 Octopus 委托分别验证支持路径。
- 查询原词、别名、目录/导航按需浏览；全文讨论读取目标全文，局部问题读相关上下文；摘要与会话历史不代替当前原文证据。

## 02 — 文本来源读取、查证与关联图片

**Blocked by:** 01。

**What it delivers:** agent 使用同一查询路径查证 MD、TXT、HTML，定位关联图片；用户能辨认文本读取问题。PDF 本轮保留，不做内容处理。

- 原件保留，提取与索引可重建，文档身份和 revision 一致。
- 文本读取范围、来源版本、读取问题可查询；图片引用与物理资产保持。
- 工具/tmp/配套静态资产不进入默认笔记搜索结果或模板；明确指定或关联阅读可按范围读取文本/图片，分类不能仅凭扩展名决定。
- PDF 只登记路径/身份，原件及引用保留，当前索引和维护流程不能自动触发 PDF 提取、OCR 或视觉读取。
- 来源变化触发更新或明确过期状态，不能用旧提取结果引用新原件。
- 用真实本库问题评估多格式检索、中文提问、同义提问和来源引用。

## 03 — 人的统一写入、版本与 app 接口

**Blocked by:** 01。

**What it delivers:** 用户经 Sapphire 或知识接口编辑主库，获得同一套版本、冲突、审计和恢复行为；框架提供后续 app 增强可调用的接口。

- app 绑定账户和具体库，复用现有 auth；app token 不成为其他库的通行证。
- 当前 Sapphire 保存/导入/回收站/恢复/Git 修改纳入共享规则，两个 writer 不独立运作。
- 修改按 expected revision 校验，冲突保留成果，不覆盖新版本。
- 修改留存可恢复内容、caller 和原因，历史恢复创建新 revision。
- 文件、附件与链接保持稳定；模拟现有 app 请求验证兼容路径。
- 普通保存只更新索引并标记受影响整理区待刷新；不自动改写或启动 Weber 入库任务。区分用户自写要点与 Weber 生成区。
- 后续 app “入库并整理”传入本次新增文件清单；明确刷新旧文时只维护选中文件。反向关联由索引呈现，不需要写回旧文。
- API、失败响应与权限形成可直接用于 Iterate 的真实文档；本票不开发新增 app 界面。

## 04 — 统一维护入口与 Weber 工作流

**Blocked by:** 02、03。

**What it delivers:** `/wiki maintain` 统一承接新材料入库、本次新增文件整理和明确范围的旧文维护，由实际 Weber 完成持久任务；日常入库只修改新增笔记，原文保全，并返回状态和产物。

- 提交可去重/幂等；普通聊天不自动提交。
- 不再要求用户调用 `/wiki submit`；接收、保存、排队与整理作为维护内部步骤。无材料/范围的命令不能自动维护全库。
- 队列有进度、取消、重试、重启恢复、失败原因与真实产物关联。
- curator 权限绑定 agent 身份，模型输入或显示名称不能伪造授权。
- 维护绑定写入清单：日常入库只写本次新增笔记及获准新建知识页；关联旧文可读但不修改其正文、标签、Key note、导航或反链。服务端拒绝扩大写入范围，重名/重复不覆盖旧文。
- 新笔记复用 Library 分类，无匹配则放 Library/Inbox；独立概念/主题仅在必要时新建，已有 Markdown 直接作来源，不逐篇复制来源卡。
- 来源、概念和总结有可核查的关系、revision 与定位；过期来源可识别。
- 原文重構完整保留原始片段、代码、公式、引文和前置字段；新增内容明确归属与来源。
- 模板缺项保持未知；矛盾另行说明；用户立场、有效决定、原件删除不被自动更改。
- 采用用户确认的轻量要点、标签、关联规则，优先保留既有核心观点；不要求对用户提供的 AI 总结逐句重新考证，不默认每篇新增内容独立模型复核。
- 接口/维护流程先在隔离环境验收，不提前修改生产 Weber 或旧库。

## 05 — 实际 Weber 配置与真实角色验收

**Blocked by:** 04。

**What it delivers:** 实际 Weber 保留思考伙伴身份，使用已经验收的知识接口，仅在显式知识任务中查询或维护。

- 读取当前实际配置并保留恢复点；保留模型、backend、credential、会话和私有记忆。
- system prompt 去除按相关性自动查库和一般文件工具直接维护的旧规则。
- 长期 persona 保留智者、读书和思考伙伴，带简短表达/总结原则；查询参考 my-wiki，完整维护写作与风格参考 Pika 并按任务加载。没有常驻全库摘要。
- curator 绑定真实身份，不依赖 prompt 自称 Weber。
- 普通讨论、显式查询、受控维护三个真实场景均验收通过。
- 验证现有/未来其他 agent 的显式接口访问；不把所有读取请求绕经 Weber。

## 06 — 首次旧库全量整理与恢复验证

**Blocked by:** 05。

**What it delivers:** Weber 对当前主库的全部约定文档形成逐项可核查的来源、组织与维护结果，保留物理结构和原文。

- 重新盘点全库文件；仅普通 Markdown、TXT、HTML 及必要关联图片进入整理。PDF、工具、临时和配套静态文件保留并列为排除资产，不套模板或自动提取蒸馏。
- 整理前快照涵盖文本及二进制原件，验证恢复方式。
- 首次旧库整理作为独立批次，先展示 2–3 篇代表性样稿，用户确认风格后再处理约定范围；日常新材料入库不能触发这批旧文整理。
- 每个文档有实际产物或明确质量问题/待处理原因；报告不以抽样替代全量清单。
- 既有正文逐字保全，路径和链接保持；新增摘要/解释有归属与来源。
- 跨来源主题和概念可以检索并追溯；已有核心观点保留，新增关联实际指向已读内容，按轻量自检发布，不伪称独立语义认证。
- 并发变化被版本检查识别，冲突成果保留；恢复作为新版本执行。

## 07 — 全规格验收与 Sapphire Iterate 交接

**Blocked by:** 06。01–05 为其传递依赖。

**What it delivers:** 用户获得验收过的框架能力、Weber 与旧库整理结果，以及可复制到 Sapphire Iterate 的准确 prompt。

- 项目要求的全部 backend、frontend、TypeScript、两个 E2E bucket 通过；真实 CLI skip 不算通过。
- 验收覆盖无关任务零新 KB 访问、引用、隔离、并发、恢复、角色和旧库原文保全。
- 按本地服务工作流交付，保留配置、auth 和已有未提交工作，前端需要时完成构建。
- Iterate prompt 使用实际 API 名称、认证、版本/冲突和维护任务语义，含明确界面需求与验收标准。
- prompt 保留现有 Sapphire 功能，复用 Octopus app-agent，概念/索引不成为第二主库。
- Sapphire 新增界面由用户随后在 app 中执行；不误报为本次已实现。
