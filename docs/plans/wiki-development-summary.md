## 2. 最终产品选择及其理由

| 决定 | 解决的问题与约束 |
| --- | --- |
| 一份主库正文，多种入口共享 | Octopus agent、Sapphire、SmartReader 不各存一份权威知识；主库存放在应用 data 内不意味着核心依赖该 App 启动。 |
| 查询、普通保存、维护分别处理 | 普通保存只更新文件/索引；聊天和搜索不自动沉淀，明确任务才进入维护；避免一次小修引发全库重写。 |
| 现有文章原位维护 | 当前文件就是正式文章，保留路径、身份、原思想和表达；不逐篇创建永久原稿副本，不搬迁为参考项目的目录体系。 |
| 程序保证权限与字节，模型负责理解 | 身份、版本、范围、读覆盖、未选字节、回执和恢复可验证；摘要是否准确、条件是否保留仍需内容判断，hash 不证明事实正确。 |
| 不按 AI/人工作者限制维护资格 | 人工改过的文章可以继续纠错；只在当前版本定点修改，不认领作者、不重新生成整篇正文。 |
| 复用有价值的知识页 | Concept/Topic/Synthesis 可直接支撑适用问题；精确数字、引文、冲突或来源更新再追必要原文，不每问重读全部来源。 |
| 维护范围明确到对象 | 有依据的 `[[关联]]`、派生反向关系及必要导航入口配套允许；关联不赋予旧页正文重写权。专题正文更新保持指定对象，新知识页按有限创建范围处理。 |
| Markdown 为本期搜索和新维护范围 | `.md/.markdown` 兼容大小写；非 Markdown 原件和历史保全，已知 HTML/TXT 仍可直接读取；PDF 自动理解未交付。 |
| 按需要增加知识和技术 | 不为每篇材料强造 Concept，不定期让模型扫描全库所有句子，不无条件上向量、重排或图数据库。 |

## 4. 当前运行合同

### 查询和证据

所有有效账户内 agent 均可按任务需要查共享 Wiki，不要求先询问 Weber 或输入 `/wiki`。只读与旧 Off 只收窄维护权。已知身份/路径直接读；否则保留原问题命名对象，用 compact 导航定位：明确文章用 lookup，具体问题用 question，宽主题用 overview，多方比较用 compare。

索引卡和 snippet 只作导航；实际读到的当前摘要、Key note 或知识页已覆盖问题及条件即可回答。缺少定义、理由、条件、出处或另一方观点才补相关正文。明确整篇总结/评价则从 0 沿 `next_start` 连续读到 null，同一 revision 覆盖全文；工具预算不构成全文上限。比较需各方依据，未读/失败范围不算已读。

回答保留主张、支持理由和必要条件，区分原文观点、转述与自己的推导，并附实际路径/位置、简短 confidence 和必要限制。检索分数不等于正确概率。个人背景只从当前 `Library/Me` 定位和读取，缺失字段如实说明，不能用收藏文章或在读身份补出职业。

精确身份 lookup 不被广义相似度替代。直接、已解析的重复表示可归并；共同标签、参考文献或综合同时引用 A/B 不代表它们是同一个作品。知识页的复用价值与独立证据数量分别判断，`generated`/`stable` 不等于已核验事实。

### 维护和日常增量

普通 agent 和普通会话 Weber 可按任务提交精确 paths 或完整 material；实际正文修改仅由框架绑定的 Weber 有效 assignment 执行。普通委托、文内指令、状态查询、来源字段和“已打开文件”都不授写权。已有文件传精确 paths、material 留空；未保存新材料才提交完整原文及已知来源，不能先创建同名文件再当新材料创建第二次。

`/wiki维护`、`/wiki 维护`、`/wiki maintain` 共用后端解析。没有对象和附加正文的裸显式命令才选择 Library Markdown 增量，指定对象则保持指定范围；唯一短名可定位，重名歧义拒绝。普通任务不会因存在状态接口而获得裸命令的全 Library 选择授权。

`maintenance_status` 有界提供当前身份/revision、合格维护基线、来源警告、未完成尝试和已知历史路径入链。基线取真实 worker 任务中已接受、已索引的输出；普通 save 不构成维护，旧维护操作即使记名 `save` 也须满足任务、单项及发布落定条件。版本相同不能掩盖来源警告或待恢复任务，状态不代替正文阅读或触发恢复。

游标绑定账户、注册、筛选及一致快照中的收据和任务落定状态；状态接口不返回正文、原始错误、理由或敏感附带值，links 不透出 query/fragment/标签。可行动复核复制返回的 typed review/review_key，在准入锁内再次核对身份、版本、可信选择、基线、直接依赖与索引；安全重放与首次新入队分开，防止旧观察换绑新对象或内容回退误复用旧成功任务。

纯移动/改名若身份和版本未变、索引就绪、无来源警告及待恢复工作，观察后停止，不为制造完成记录再排 `no_change`。旧名字面链接另查当前影响；其存在不证明是这次移动新造成，未选关联页的正文保持只读。人工编辑后以当前内容、删除和未知字段为权威，完整复核可以合法 `no_change`，不强制文章壳或让简介穷举个人信息。

### 内容与受控操作

文章、个人短记录、导航、模板和综合按用途组织；Library 目录大分类、细粒度标签、必要关联，不统一套外部文章模板。保持原思想、理由、条件、否定、反例、引文、公式、代码、媒体、锚点和风格。已有准确要点沿用，缺失摘要由 Weber 理解后生成；新解释与原文归属清楚。

来源可空，不造作者、日期、出处或 verified；库内依据使用真实 doc/revision/location，外部文件路径/字节/hash 是接收范围记录，不能伪装库内引用。服务端保持 uid 和未知元数据，省略来源/标签不等于清空。可移植身份别名不代替服务稳定 id，也不产生权限。

`organize` 用于合法原位规范化，`restructure` 保留原块做结构重排/追加，`revise` 绑定当前 raw locator/hash/expected_text 定点纠错或补充，`publish` 只新建必要页。read 的提取文本坐标不能直接当 raw 坐标，Unicode code point、UTF-16 和字节不得混用。保护拒绝后不能拆小删除绕过；新证据不同于旧观点时保留主体和语境，不擅自替作者换立场。

worker 写前读当前任务所需范围；整体整理和复核读全文，局部修订读相关位置与必要上下文。终稿冷读覆盖该 job 的全部最终新增/修改区段、标题和必要邻接上下文，后续再改正文便重新覆盖，旧任务阅读不跨任务继承。未选字节由程序保全，含义与表达仍由模型检查。

普通会话启动时只常驻简短 Wiki 能力入口；使用 Wiki 时按需取得 query/entry/retrieval 指南及当前操作卡。load_guide 在同一次授权视图中返回公共规则、模块正文、操作卡和实际正文 digest；已有完整指南先按当前操作卡的 guide_digests 核验后复用。整包 guide_hash 不能区分 auto-entry 与显式 entry，不作为正文缓存键，也不授予权限。未使用 Wiki 的任务不预装查询或入库指南。

worker 先按需加载 worker 基础合同，再按需加载 maintenance/article/writing 指南；只有有效当前 assignment 才开放这些维护模块。取消、结束或注册失效后，旧卡与旧 digest 不能恢复授权。worker 根据服务回执、输出版本和索引结束本轮，框架在模型返回后确认 job 终态，不能在任务内等待自己的 job 完成。

Codex 控制指令的当前交付生命周期见[运行时计划](codex-backend.md#54-instruction-injection--solved--c-developer_instructions)：正常续聊和重启恢复复用最新稳定检查点，规则真正变化才更新；本轮来源要求与一次性分叉说明单独交付。历史 A02 的每轮 full snapshot 不再作为当前交付策略，原有过期 Wiki 禁令迁移能力继续保留。

内部任务只捕获文档及创建预留身份，卡片中的路径从当前 grant 投影，不另存旧路径或新页布尔授权镜像。原位整理保留单一目标；App 的准备和跟随任务分别由 task→owner 字典登记，失败任务与真实 writer 退休语义保留。后继选定修复沿用这些简化，并补齐持久通知、原执行交接与 owner 恢复，不扩展其他条件项。

### 恢复、存储与性能

同一正文在本次索引或链接校验操作内复用格式解析的 CommonMark tokens、render env 与原坐标映射，搜索章节和引用投影不重复解析。tokens 可被 renderer 修改（如图片 alt），仅归当前正文和当前操作所有，不跨请求缓存或持久化；延迟执行的 catalog 仍按当前正文解析，layout 仍独立检查原始插入片段。解析/搜索版本、原文坐标、YAML 错误保留与持久来源合同不变。

稳定 id、revision、job/item、来源、receipt/change 和索引共同证明实际结果；排队、模型自述、文件存在和退出码均不能独立证明维护完成。取消不回滚已提交结果，失败只续未完成项；已保存但索引失败只恢复索引，不能重新生成。恢复检查当前版本，不能覆盖后来的人工编辑。

任务 items 沿用原 JSON 列，通过统一版本化 codec 兼容读取；旧标志和未知字段作为原证据保留，不全表规范化重写。每批 ExecutionRef 固定原 attempt/session/request；历史引用可供核验，只有当前引用可以推进执行状态。正常完成、取消与启动恢复共用效果核验，已发生的部分输出和未确认终态都保留为 attention，不自动调用模型补齐。

取消由原任务的唯一取消工作关闭 scope，并等待所有批次已捕获的后端、Research、后台进程及文件线程退出；单个清理失败仍等待其他清理，最后报告失败，HTTP 等待超时仍是 pending。Registry 用尚未发布的候选完成 observer、history、索引和任务恢复后才借出 Store，同 vault 同服务代串行完成恢复；注册变化也等待旧构造退出，任务分类与旧 writer 退役标记在有效注册锁内提交。普通读写加锁不触发历史恢复。受管启动提供的旧 writer 已退役证明只用于原引用，不把未知执行改成 pending。

任务详情分页读取完整错误、原执行和输出回执，保留 no_change 原因；jobs 原行按 attempt 保存完整诊断，即使 ingest 或请求准备前失败、尚无执行引用或 items，重试后仍可读取。历史输出按原 receipt/hash 读取，当前正文按稳定文档身份定位移动后的路径。查看只执行 GET。核验原效果和索引、继续已知未完成项、有限 scope 重新准入是三个显式动作；后两者仍要求原资源退役和当前权限，控制操作标识在响应丢失后复用，不能因此新增尝试。

注册变更后的显式 scope 再准入保留同一文档的原请求录制未确认引用；后续恢复仍须核验原请求的持久终态，再确认输出并归档原会话。重新选择的当前版本和有限写权限继续独立校验，录制引用不能转移到其他文档。

存活原会话仍有录制阻塞时，再准入继续返回 409。先确认原执行和后台清理已退出、没有待调度请求，再通过原会话的 `dispatch/resume?resume_queue=false` 对账录制，保持原调度状态；存储仍未确认时返回 503，不进入再准入或重跑模型。对账成功后，显式再准入和原请求恢复继续各自校验，再准入仍保留全部排队、后台清理和实际写入退休检查。

维护输入缓存 `maintenance-inputs-v8` 以 job↔doc 并集表示影响范围，五类事实来源及旧/新身份失效均保留；状态经同一 codec 解码，确定排除的旧成员保留证据但不再派发。纯进度更新只使相关投影失效，成员身份变化才核对关系并写入增删差异；相同状态和仅更新时间不重新使维护判断失效。job 版本及通知仍在原事务内记录。沿现有事务重建缓存并换 nonce，不修改持久任务和来源事实。旧分页游标及旧计算失效，语义等价的 review/review_key 和稳定 selection 不因缓存重建额外失效。旧 `wiki_edge_lookup` 索引退出，`lookup_key` 的计算和值仍参与完整依赖摘要及旧迁移证明；不能写空值或删摘要字段来代替索引清理。

原始块读取使用同次 Store snapshot 的正文与版本。每个 Store 只保留最近一份 revision 的不可变块坐标、hash 和章节标签；不保留全文、可变 tokens、权限或阅读覆盖，分页只装配选中的块。每次请求重新核对当前身份、revision、来源和授权，只有实际返回的正文计入阅读覆盖。`no_change` 仍核对当前正文、维护资格及完整阅读，并记录原版本回执；不为无编辑操作解析或装配原始块。

主库正文唯一，保留正常按文档有限历史与必要任务/失败证据，不默认长期整库备份，也不自动 Git 提交知识库。Sapphire 继续负责文件、附件和 Git 体验；本机此前一次主库 Git 保存不授权以后每次保存都提交/推送。

当前代码的完整 Wiki 格式为13，版本权威仍是 `wiki_schema` 的最大版本。新库一次建立含 jobs 的完整布局，只记录13；支持的12布局可有 jobs 或确实从未初始化 jobs，前者保留全部任务、授权、控制、通知和 ACK，后者须先排除持久任务引用。准备、绑定及版本在原存储事务内共同提交；健康13只验证，不重跑旧安装步骤。结构与协议只读准入先于 writer、观察器和注册发布，无支持路径、未知结构或缺失持久账本均保留原资料并拒绝。基线之前的 schema 转换及注册 generation 自动补写已经退出；安装层仍保留旧配置的根排他保护。

已知派生投影仍由原 owner 重建，维护 nonce 随实际重建更新；正文、来源证明、历史和原通知事件不作为缓存清空。主库接纳提交后才 ACK 原 outbox 事件，重送继续使用原事件去重。旧 item 编码和保守 journal 恢复仍按当前合同解释，不能仅凭格式13认定旧内容已转换。恢复使用支持当前格式及协议的已验证代码或前向修复，不以旧数据库覆盖新写入，也不维护第二份知识库。实际运行提交和格式以发布验收为准，代码更新不表示生产已经升级。

文件事件协议仍为1；已观察事件先持久接收，再将身份/索引应用和 applied 标记原子提交，最后精确确认。观察器中断、overflow、armed/uncertain 等不确定证据失败关闭，不丢队列伪造 ready；未被观察到的离线瞬时历史不能追溯。Store 生命周期、后台对账与关闭等待保留真实 writer/线程完成语义。

查询热路径不重复全库回填/扫描；改动增量更新。默认导航/读取 compact，原生读取完整 MCP 结果上限 32,768 UTF-8 字节，不是 token 或整篇上限。任务默认小摘要，按固定 key 服务端定位；full/export 返回文件、字节数和 SHA，用短程序读必要字段，不把大 JSON 塞入 shell 参数。

## 7. 整个流程中可以优化的地方

| 观察到的现象 | 原因/影响 | 更好的做法 |
| --- | --- | --- |
| 早期曾先写未集成脚本、安装 PDF 依赖，再回头确认规格 | 范围和实际入口尚未稳定，产生需撤回的代码与额外环境状态。 | 先固定用户行为、现有入口和完成条件，再选择依赖；不为未启动的功能先装整套管线。 |
| 多份“当前 spec/进度/交接”同时存在，研究和运维也混入旧执行指令 | 接手必须拼十多份文档，旧状态容易覆盖新事实，已关闭 R08 仍被列为未做。 | 总结负责交付/合同与必要理由，未来计划负责剩余需求，local-wsl 负责操作；历史稿退役时一并修正引用，不复制续接长 prompt。 |
| 首行选择、wrapper、App 事件和生命周期边界反复出问题 | 只测试内部函数，未覆盖实际可信输入和真实请求归属。 | 从用户入口写合同与反例，固定 request/doc/revision/actor，先验证模块交界再扩大实现。 |
| 为几篇材料附加长审计 prompt，控制器承担大量逐篇提示 | 测到的是被指导的工作流，日常 Weber 仍依赖临场补救。 | 规则在共享指南和程序守卫固化；普通最短入口另行验收，评阅材料留在模型上下文之外。 |
| 大 JSON 经模型复制进 shell 引发 E2BIG | 数据搬运反复消耗上下文，还触发 OS 单参数长度限制。 | 小摘要定位，完整结果直接导出，短程序核路径/bytes/SHA；不再打印、拆分、重构整份返回。 |
| 任务 completed、工具成功、冷读完成被混为一项 | 声明覆盖与实际内容不一致，或保存/索引/通知阶段不同步。 | 分别核接管、worker、receipt、输出版本、索引和实际读范围；收尾从真实返回解析，不手填成功摘要。 |
| 参数探针、付费检查和部署 helper 出现重复轮次 | 没有先固定版本、依赖和验收问题，结果失效后成本被抹平。 | 发布前冻结候选；未受影响检查按精确依赖复用；新增实际失败仍触发相应复验，首轮失败和用量保留。 |
| 回执尚未生成就发出 r2 审查和 SHA，文档检查又被并行源码变化拦住 | 把计划中的产物当成既成证据，并把任务范围误设成整个工作树。 | 先读取命令退出码和真实产物，再计算版本并交接；检查绑定本任务路径，范围外变化另记，失败/取消不算通过。 |
| 为每次发布重做知识问答，固定 gold 和当前资料发生冲突 | 将自然措辞/可变化个人事实当成确定性机制门禁。 | 确定性合同是发布门禁，自然知识质量独立 opt-in；资料版本和评阅标准事前绑定，不改 gold 追认。 |
| 临时认证、部署排空和切换由多份脚本重复拼装 | 更容易遇到数据库锁、旧票据或在途回报被打断。 | 复用已审查入口，发布状态单一负责；切换前就地校验新鲜度，真实自然排空，最后才退役旧源码。 |
| 文档记录也多次单独 commit/push | 增加交付往返和历史噪声，业务源码没有变化。 | 文档持续更新工作区；仅用户明确要求或随相关代码交付时提交，文档不触发重启或全套实机检查。 |

这些是本项目过程推导的改进，不是已测量的统一效率增益。安全和数据保全所需的独立 worker 阅读、版本校验及异常复核仍保留，不能为了减少工具数省掉真实边界。

## 8. 后续默认开发方法

1. **先定问题和完成条件。** 核当前源码/运行/用户约束，描述具体触发、正确行为、可观察产物与不属于本次的范围；能查清的实现问题不交回用户重复选择。
2. **先复用，再定位最小完整改变。** 从现有任务、锁、历史、解析和 UI 开始；用一个稳定复现识别根因，覆盖同类场景而不按当前题名特调。必要的数据迁移/恢复随功能一起完成。
3. **把验证分层。** 纯机制用隔离、可控事件门和真实协议；高风险行为及公共接口请 Vera 独立审查；模型理解用少量代表材料/普通入口，额外试验只有具体证据缺口才增加。
4. **规则一次写对地方。** 程序管权限/事务/恢复，schema 管参数，常驻 prompt 只放短原则，按需指南管任务步骤；persona 保留思考伙伴身份。文档也分工：决策理由、来源依据、当前合同和操作步骤各有入口，动作授权只维护一份，不把研究建议直接变成操作指令。
5. **按任务冻结并验证。** 先核实命令退出码、实际回执及版本，再发审查或收尾；范围限定到本任务，保留并行改动。所需检查通过才交付代码；依赖未变可按 SHA 有限继承，失败/跳过/未测分别报告。不要一边改被审文件一边把旧审查当成新批准，也不为低风险文档改动复制全套发布仪式。
6. **从真实入口验收。** 事前登记问题、材料版本、配置和预算；无额外引导发首轮，失败留证，修后重跑明示为复验，不把已见样例称盲测。普通查询、入库、worker、评阅成本分别记录。
7. **按行为边界提交与发布。** 用户已授权的代码工作完成本机门禁后，聚焦提交本任务代码和必要相关文档，再推送/自动发布；排除其他并行工作，本机可用 Codex 约定见 AGENTS。纯文档改动留在工作区，不自动 stage、commit、push、构建、重启或模型检查；用户明确要求文档提交也不触发发布。
8. **收尾以事实为准。** 代码发布核实际 PID/cwd/源码与资产、当前 schema/索引、关键产物和用户数据；不恢复旧 DB 覆盖新写入。只有事实变化才更新负责该内容的文档，完整日志留任务产物，memory 只记稳定约束；停止重复成功工作。

## 9. 仍然有效的证据边界

测试项数取各次实际日志，不能跨版本相加变成“本次通过总数”；部署验收不认证所有文章外部事实，局部语义抽查不冒称全库逐篇正确。源码快照共享本机依赖，不提供操作系统级 App/agent 文件隔离。取消等待不等于底层线程已停止；索引 ready 不恢复未观测历史。完整来源谱系、自动独立证据计数、多账户压力和所有语言/题材的最佳效果均未获普遍认证。

未完成需求和明确不自动推进的事项集中在[未来计划](wiki-future-plan.md)，不再通过旧停止位置或复制旧任务稿启动。
