# 本地共享 Wiki v2：保留思想与表达的定点维护

> **Status:** in-progress — revise、raw blocks、读取覆盖、回执/恢复合同已实现并上线；真实完整试点和全量验收仍在进行，见[当前进度](local-shared-wiki-progress-v2.md)。

更新：2026-10-13。权威原则来自[设计访谈](local-shared-wiki-grill-v2.md)：正文曾由人编辑或由 AI 生成，都不决定能否维护；维护不得让核心思想、论证和带风格的观点逐渐消失。允许原位纠错和有用补充，正常入库与维护不将正文重新生成一遍。

## 1. 内容规则

- 当前 `Library/` 全部 Markdown 按实际类型整理，pika_vault 优先；文章按最新模板原位规范化，保持正文论述与措辞，补元数据、必要 Key note 和关联，结构变化保留原块。正式文件就是入库文章，不另存永久原稿；已有资产 Markdown 同样纳入明确 assignment，角色与默认候选范围分开。
- 后续维护读取最新内容，针对明确问题局部纠错、补充解释或记录新的条件；旧页、已有 Key note、人工点评与生成内容适用同一规则。
- 明确笔误、错链、单位、计算或事实错误可定点修正，记录实际差异；无法确认的疑点保留原说法并说明，不能凭模型印象改成“正确答案”。
- 既有观点、判断、推测、引文和有风格的表达保留其主体与语境。新证据不同时，补充依据、条件或更正说明，不自动替原作者或用户换立场。纠正引述内容的事实问题时，保留原引文并在外部说明。
- 不涉及本次操作的字句、论证、反例、公式、代码、媒体和锚点保持。不能借“整理”删掉复杂内容、统一文风、削弱判断条件或用新摘要替换正文。
- 普通保存只更新文件及索引；明确维护才运行 curator。新文入库关联到旧页不扩大可写范围，旧专题更新仍需属于本次指定目标。

这些规则按内容和操作判断，不要求逐段鉴别人或 AI。服务端验证位置、范围和未修改字节；含义、观点与风格的保全仍需自检、冷读和真实内容验收，不能宣称 hash 检查证明了语义正确。

## 2. 模板化、纠错和补充分开执行

| 动作 | 合法结果 | 正文处理 |
| --- | --- | --- |
| 模板化 | 已有文件原位成为规范文章 | 保持论述与措辞；结构调整保留原块，新增要点与正文分开 |
| 定点纠错 | 明确错误得到修正 | 仅替换实际错误位置，保留上下文与观点归属 |
| 内容补充 | 相关位置多出有用说明、条件或新证据 | 插入而不重写周围正文，不把补充冒充原作者原话 |
| 来源复核 | 实际检查过的依赖更新记录 | 原解释仍适用可不改字；未检查依赖保持原状态 |
| 无需修改 | 当前内容已满足本次任务 | 记录实际检查与完成回执，不为了结束 job 再造摘要 |

新知识页允许首次写作；成为已有文章后按同样的定点规则维护。未读到原材料时不能创建声称保留原文的 Reference。

## 3. 已实现机制与兼容边界

v2 已实现新版 organize 原位保全、restructure 原块重排/追加、revise 定点纠错/插入及持久 no_change，publish 只新建。旧 organize 请求继续兼容，人类全文保存不是 agent 的定点协议。底层 history.write_locked 提供库锁、当前版本、原子写入、prepared/applied journal、有限历史与恢复；已有资产 Markdown 资格扩展的实际运行及最终冻结版验收见进度页，不由旧索引版本推断其是否加载。

V2-02 的独立受任务约束修订分支不经过 `original_text → 删除旧生成区 → 重建` 路线。旧 ownership 记录用于历史兼容、定位和恢复，不作为人工内容不可编辑的门禁；修改涉及旧记录时更新或撤销对应定位并保留历史。

## 4. 工具与原始位置协议

已实现 REST `POST /api/wiki/revise`、MCP `revise`，已有 app 网关转发同一合同。consumer app 仍只提交限定维护任务，不直接取得 curator 写权限。能力标识 targeted_revision 由实际运行版本声明，旧工具保留兼容，未实现的 region_updates 草案由本合同替代。MCP 参数为 request 对象，REST 直接接收该对象。

`blocks` 扩展可选定位视图与指定块读取：默认旧响应保持；新视图返回当前版本的原始块定位、hash、标题和范围，按需读取正文。块定位绑定文档身份及 revision，不把当前数组序号当长期身份；实际返回的原始区间进入任务阅读记录。

定点补丁示意：

```json
{
  "doc": "<当前文档 ID>",
  "expected_revision": "<已读取的当前 revision>",
  "operation": "patch",
  "reason": "修正明确的单位错误，保留原论述",
  "edits": [
    {
      "locator": "<blocks 返回的 revision-bound 原始块定位>",
      "expected_block_hash": "<服务端原始块 hash>",
      "start": 12,
      "end": 14,
      "expected_text": "<该范围当前原字句>",
      "replacement": "<修正后的字句>",
      "kind": "correction"
    }
  ]
}
```

start/end 是该原始块内 Unicode code-point 零基半开范围；hash 针对原始字节，expected_text 必须逐字匹配。新增说明使用 `kind=addition|annotation`、start=end 和空 expected_text，在指定位置插入。

read/search 的位置属于提取文本，不能直接传为原始块位置。UTF-8 BOM、CRLF、HTML 提取和渲染会影响映射；必须通过 blocks 的当前原始定位，或服务端已验证的映射转换。首个定点编辑实现限直接可编辑的文本正文，HTML 抽取位置不允许盲切原 HTML；HTML 原件的模板化继续沿已定义的阅读页转换流程，源文件改写需要独立格式合同。

## 5. 服务端提交合同

- 检查真实 curator 任务、当前有效 assignment、文档身份及明确目标范围。授权来自任务，不来自 type、generated、uid、来源字段或旧区段归属。
- 模板化、整体组织与新综合完整读取当前目标；明确局部纠错至少读取修改位置及必要上下文。blocks 实际返回原文也须登记对应覆盖，不能只在 prompt 中声称读过。
- 在同一库锁内校验当前 revision、原始块 hash、expected_text 和读取覆盖。过去有人改过不构成冲突；读取之后内容再次变化才要求重读或报告冲突。
- 对单篇的多个补丁检查范围、不重叠与唯一定位，原子应用。没有正文整页 `content` 替换分支，也不以整段生成区替换代替具体纠错；未选择字节由服务端原样拼接。最终存盘写完整文件是原子存储方式，不表示模型获准重新生成全文。
- 元数据适配复用共同 `frontmatter_patch` 白名单和 tags/aliases 输入；省略即保留。uid 保持、实际执行身份写入历史；不通过模型声明核验或改写未知字段。正文修改不附带重做标签、摘要或关联。
- 当前文章来源可以为空；缺少出处不阻止模板化、局部纠错或补充。未提供来源更新不清空已有 sources；对实际新增或修订内容的出处按明确更新记录，保留未涉及的引用。
- 保持未请求改变的标题和 block 锚点；结构整理确实影响锚点时更新真实解析/链接状态，不把“新增链接检查通过”当作全部旧链接仍有效的证明。
- 输出实际 changed ranges、当前 revision、change/history、任务产物回执和索引状态。发生纠错时准确表示内容有变化，不继续声称整篇 `original_preserved=true`。

## 6. 复核、无变化和任务恢复

同一 revise 工具提供独立的 `operation=confirm_sources` 和 `operation=no_change` 分支，schema 与 patch 互斥；空 edits 不隐式充当成功。

confirm_sources 明确指定本次检查的直接依赖记录和来源当前版本，核对实际读取；解释仍适用时仅更新对应复核状态，保持正文，不顺带认证整页。已知来源不可用时记录真实缺口，不能解除为“仍有效”。no_change 针对当前内容实际满足本次任务的情况，核对目标版本、读取记录和说明，保存完成回执。

新建、模板化、追加、定点纠错、来源复核和 no-change 都进入持久 job 产物记录。多次修改同一 item 时记录真实序列及最终产物；重启先恢复 prepared/applied 和已完成回执，不重复生成或重放补丁。索引故障只重试索引，不再改正文；无文本变化不伪造文本 change。

取消后不开始新的修改；已提交修改保留真实历史，写入线程完成日志收尾。取消不承诺回滚已提交补丁。恢复或批次回滚核对当前版本，不能覆盖之后的用户编辑。

## 7. 文章来源与变化提示

本期记录可选出处、可回查链接与程序确知的直接总结/表示关系；已知来源变化时提示直接依赖内容。普通相关链接不传播证据变化。未有明确依赖的文章不要求补齐谱系，系统不认证每条观点的正确性。

实际修订涉及哪些依赖就更新哪些，实际复核哪些就解除哪些提示；没有检查过的来源不被刷新。完整来源根闭包、自动独立证据计数和深层传播不作为核心门槛，按总纲 §10 的条件项处理。

## 8. 工作流与长期保全

Weber 对照原文与候选差异，检查原思想、主体、判断强度、反例和有风格的表达是否保留，再冷读修改位置及必要上下文。原位纠错不顺带润色整段；新增总结不循环重写原正文或既有总结。

反复维护同一页时，每次只处理实际问题。详细变化留在 history 与任务回执；需要解释旧观点与新证据关系时，用简短、可读的新增说明保留语境，不在正常正文堆积内部日志。

## 9. 必需验收

1. 当前 pika_vault 模板化保持正文措辞、论证、引文、公式、代码和媒体；结构调整与新增要点准确记录。
2. 人工改过的旧页和生成页均可从最新版本定点纠错与补充；读后再变化才冲突，不按作者类别拒绝。
3. 局部修正只改明确位置，未选择字节保持；BOM/CRLF/中文/emoji/重复句、原始与提取位置、标题/块锚点均有用例。
4. 多次补充和纠错后，原核心思想、有风格的观点、理由、反例与关键条件仍可找到，不能被新摘要逐步替代。
5. 无来源文章可整理；省略来源不清已有记录；confirm_sources/no_change 有实际阅读与真实回执，不为结束任务改字。
6. prepared/applied、重启、取消、部分写入、索引失败和恢复准确，已完成动作不重复执行。
7. 真实研究问题完成知识建立→不同问法复用→明确纠正；机械用例不代替含义与复用检查。

## 10. What this defers

- Sapphire/SmartReader 的新交互及直接修订 UI 仍属 App feature plan；核心提供已有入口兼容的任务与服务合同。
- 完整来源谱系、自动证据计数按 Q57 不作为本期要求；需要实际使用缺口再设计。
- 本轮保留 PDF 排除；任意 HTML 源码正文的定点编辑需要独立源坐标及格式需求，当前不以提取文本冒充源文件位置。
- 这份设计不执行当前 Vault 模板化、正文修改、历史清理或部署；实际实施与运行记录分别更新状态。
