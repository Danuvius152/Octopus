行为验收

值得保留的深度与边界

数据库事务已有深度锁、短事务、取消、驱动结束和提交失败由 Database.transaction 统一承担；不要为了拆文件引入 ORM 或多套 repository。
完成并非一个布尔值轮次结论、结果记录、通知送达、执行退役各有证据。把它们合并会丢失现有保证。
前端已有可用参照accountFetch 的账户代际、dispatch 完整快照、hydrateSession 的消息/问题合并、transcript 的窗口和 seq 各有实际责任。
Wiki 效果不能靠模型结论替代History 原像、操作 receipt、来源版本和读证据属于正确性机制；不以“减少代码”为由合并或删除。
次级机会：输入接管/恢复的前端编排、数据库完整行的列映射、Research 的重复 Task 登记。前者需有近期变更需求；后两者收益较小。取消浏览器收讫账本、删除无数据库执行路径则涉及合同变化，不能当作无损清理。本报告不提出新接口签名，也不恢复已暂停的执行扩展。
