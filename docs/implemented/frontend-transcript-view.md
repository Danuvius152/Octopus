## 实时历史身份与流缓冲

持久 seq 是会话内消息身份；`lastAppliedSeq` 保存已接纳权威快照的拒旧水位，
不由实时 WS 最大 seq 推进。`applyTranscript` 只调用一次 store 的 `installTranscript`，
在同次提交中完成拒旧、历史合并、流收束、窗口身份、游标和覆盖发布；调用方不再
排列独立的窗口／水位 setter。首次确认空历史也安装显式 `-1`，不能与未加载混同。
呈现基线要求覆盖及配套游标元数据同时存在且完整性合法。raw clear 或损坏撤销
安装资格、退休窗口，却保留拒旧水位；迟到旧 WS 仍不能清掉新流，合法 detail 可恢复。
等价空刷新只有覆盖、游标、has-more 与完整性均相同时才保留窗口；未知变为确认空
仍建立新窗口。WS 在事件 switch 前按覆盖和当前窗口已有 seq
去重，store 的直接写入也幂等。未见的低 seq 可补入：在第一个更高的持久 seq
之前定位插入，其余按普通追加处理，不全数组排序而移动已有无 seq 本地命令／通知。
这保护历史与控制效果两个入口，不新增全局已见集合或持久 ledger。

快照保留高于其实际读行 high 的 WS 行；低于已安装覆盖的旧历史投影被拒绝，
不能降低窗口／游标或重建旧辅助投影。只有连续前缀才沿用旧游标，服务器 high
仍取实际读到的行，不使用尚未填满的分配器水位。真实 Claude 背压及投递未知的
边界见[插话顺序](inline-steering.md#live-transcript-ordering)。

`readAttemptIdentity` 统一读取 WS envelope、`runtime_metadata` 与持久
`tool_input.attempt_context`。带身份 delta 必须精确匹配当前 request/attempt，
没有 active attempt 不自动放行。已接纳的同 attempt terminal 阻止旧 delta；
已完成 native text 只终结其精确 `nativeItemKey`，同 attempt 的其他 item、复用
provider item ID 的 root/child 保持独立。无身份兼容事件保留原规则。

`streamingText` 的当前缓冲保存正文和已接纳的 attempt 归属。明确进入新 attempt
会退休旧归属的 plain/native 缓冲，无身份帧沿原兼容规则处理。服务换代、账户
退休及 forget 释放原缓冲。读取详情前取得各缓冲的轻量到达标记，安装可接纳的
新历史时保留读取期间仍接纳了新文本的同一缓冲。已接纳的 terminal 和精确匹配的
已保存 native text 优先清除对应缓冲。旧 text／result 可以补历史，原身份隔离保护
新 attempt 的流。历史投影沿快照路径安装。

关闭问题不能复活；被较新成功详情替代的旧读取不再重建问题或 active attempt。
接纳可靠 `question_answer` 或 `question_closed` 历史时，在同一次 store 提交内
写入消息、联合关闭事实并过滤当前可答集合。旧读取仍可贡献这类历史，不整表
替换 pending；同 seq WS 的正常去重不延后关闭，其他新问题与未发送草稿保留。
问题结算本身不证明模型已经收到答案，投递与草稿继续由原输入协议处理。
原生任务以 `tool_call_id` 归属原任务，委派以 `delegation_id + work_id` 归属原轮次。
迟到的持久 question_request 可进入历史，pending 仍受原 closed 身份过滤；无 seq
的已关闭临时通知继续忽略。`useWebSocket`、`transcript`、`hydrateSession`、
`nativeOutput`、`recordingReplay` 和 store 回归覆盖乱序、重连、同请求不同 attempt、
快照 terminal、新旧 item 和本地临时行；真实 QuestionLifecycle 消费者保留兼容对照。
同一子会话的下一 work 可以运行，不能按子会话设置全局终态最大值。

## 浏览器有界预览与按需全文

浏览器 WS 订阅和显式 `view=browser` 的会话 detail、历史、native-details 出口
生成可丢弃的展示投影。默认 HTTP 完整表示、持久消息、原生审计、内部 bus、App
流与 LiveReply、fork 和 typed 导出继续使用实际保存的完整记录；投影不原地改写这些来源。
首屏和重连仍通过 HTTP 读取 snapshot，不通过 WS 发送完整历史。

App Server 命令的 `output_capture.state=head_tail` 表示保存时已永久省略中段；
`body_state=preview` 表示浏览器再次缩小这份记录，两者独立，head_tail 也可 inline。
详情只补回已保存记录，不恢复未归档中段。展示转换在预览预算裁剪之前执行：
只有 `tool_result`、`output_capture.state=head_tail` 和含换行的精确前缀同时存在，
才移除一次固定前置说明。正文内相同文字、重复前缀的第二份及无证据旧文本均
保留；HTTP、WS、原生详情及浏览器全文复用该转换。默认全文、保存记录和导出
仍保留原说明；按需浏览器全文不再次裁剪。无 capture 的旧记录仍按原序列
读取、复制和导出，不补造完整性保证；原生身份过大时仍沿原 notice/详情合同。
命令保存预算与四态由 [Codex 合同](codex-backend.md#saved-command-output)维护。

实际 UTF-8 JSON 编码限制为单条消息 64 KiB、含 envelope 的 WS 事件 256 KiB、
HTTP 消息数组 2 MiB（含数组括号和逗号）。根会话/历史返回最新连续后缀，原生
详情返回最早连续前缀；消息数和字节共同限制窗口，游标取实际返回成员，不跳过
超大记录。2 MiB 不是整份响应上界；其他 envelope 保留各自的数量界限，原生
卡片最多64个，展示文字每字段最多4 KiB，步骤保留最近12条、每条最多1 KiB。
这些文字限制不截断原生身份，也不建立整个卡片 envelope 的绝对字节保证。

消息省略正文或大字段时标记 `body_state=preview`，有原持久 seq 才提供同源
`detail_ref`；大结构显示明确占位。展示不重复 canonical 正文的 native_item/
request_context 副本。单纯省略已证实的工具调用原生包装不标为预览，也不触发
全文读取；其他预览标记仍可能表示重复字段省略，不一定代表正文截短，因此聊天
气泡不逐条追加 Preview、Full message 或全文
链接等常驻说明。工具调用与工具结果沿已有箭头展开；第一次展开需要完整记录时
读取原序列，之后复用该视图的局部缓存。其他消息以悬停或键盘聚焦时出现的图标
提供全文与预览切换，触屏直接显示图标。主动读取期间显示加载状态，失败保留
已有内容并提供明确错误与重试入口。

工具调用的展开区与保存的子代理工具详情共用 `presentToolInput` 纯展示规则。
只有 `tool_use` 的原生消息身份与 `native_item.id` 对应，且外层另有独立参数时，
才在浏览器投影中省略该原生包装；主区完整保留其他实际参数。
不能根据字段名剔除 `request_context`、`attempt_context`、`id`、`input` 或 null：
它们可能是工具自己的业务输入。没有独立参数的原生记录、`params.item`、未知
兄弟字段及来源无法对应的输入保持原结构。Bash 只有 `command` 一个参数时直接
展示命令；存在超时等其他参数时一并显示。紧凑单行摘要及 RESULT 折叠样式沿用。

Asked／Continued 共用委托请求卡片：外层宽度不超过当前聊天行，长路径及无断点
文件名在卡片内换行，摘要仍省略显示并可查看完整参数。完整文字、原轮次状态及
打开／取消控件保留，不靠裁切整张卡片隐藏内容。手机与桌面的实际浏览器几何
回归检查卡片、聊天滚动区和控件边界；普通 RESULT 的保存或预览预算不负责 CSS
宽度约束。

根聊天与保存的子代理工具详情均不再渲染 Raw tool data，也不预先序列化其 JSON。
HTTP 快照、历史、原生详情和 WS 复用上述浏览器投影，减少重复包装的传输与展示
成本；无法证明为重复的输入照常保留。按原 seq 展开全文使用 `view=browser`，
仅省略相同包装，仍取得完整业务正文和参数，不重新套预览预算。默认全文接口、
原消息对象、持久数据、内部 bus、导出、模型输入和历史重放保持完整；这不减少
模型上下文 token，也不以删除 UI 推断所有工具响应都会缩小。

终态的 final-answer、compact 原生关联和控制字段优先于
诊断正文。恢复代码/尝试计数、录制缺口和派生问题提示同样是控制事实；两轮缩减
复用同一控制部分，只裁明确的正文、诊断位置或卡片展示文字，不重新按大小挑选
控制字段。result/recovery 的未知字段也保留，不能从部分事实恢复“已保存”声明。
原 request/attempt/native 身份通常完整保留；必需控制及原生身份没有统一长度
上限，连最小控制/身份表示也装不下时返回明确的 `identity_unavailable` 通知及
原 seq/全文引用，不截 ID 或伪造关联。原终态仍以有界说明显示。WS 无法表示的
事件产生可见通知；连直接回执都无法满足单帧上限时关闭1013，沿原观察恢复。
关联无法表示的记录展开后以完整只读原记录显示，包括原身份字段，不把取得全文
等同于已经把它重新关联到当前聊天视图。
WS 不可表示通知保留该标记并经 decoder/store 传入原消息视图；native-details
中的对应消息也复用同一只读记录显示原 `runtime_metadata` 和正文。
已持久问题的 WS 降级引用按原 session/seq 生成，与题干是否缩短无关；没有持久
seq 的实时事件不生成全文引用。
卡片的截短标记属于浏览器 DTO，默认完整快照保持原卡片形状。已存卡片的名称、
描述和步骤可缩成预览，原 card/task/native 关联和状态保留；其全文引用只覆盖
确实写入该行的字段，不能代表没有保存的 live prompt/summary。
展开已存卡片全文显示原序列的只读记录及完整字段；它与当前 live 卡片分开，不把
旧记录写回 live 状态，也不只读取 live 缓存却标记为已经显示全文。

`GET /api/sessions/{id}/messages/{seq}` 在同一短事务重核当前账户/会话归属并
读取完整 MessageContent；归档仍可按所属账户读取，缺失/删除404、重复seq409。
引用不授予权限，不接受文件路径，不调用模型补内容。成功及404/409详情响应为
`private, no-store`。用户主动展开才 GET，完整 JSON 接收并确认原 seq 后显示
全文；失败保留预览并可重试。普通全文的资源身份由账户、session、seq、精确
detail_ref 与连续消息窗口共同确定。body、error、busy 一起归属该资源；新身份
第一次 render 就屏蔽旧值，不等待 effect 清空。资源内重新读取替代原请求，旧
cleanup、成功、失败及 finally 均不能修改后继；同步 store 订阅在窗口或账户
变化时撤销在途发布资格。卸载取消原读取。收起/展开及连续窗口重连可复用该
挂载资源的完整记录，不建立全局全文缓存。

native-details 的 page、error、busy 也归单一资源，另包含 anchor、刷新、连接与
服务观察范围。同步退出或 Refresh 先永久退休原读者，再安排后继；即使连接在
一次 React 批次内断开又恢复，旧 More/Refresh 控件仍不能启动读取。请求次序只
裁定同一有效读者内的读取替代，旧分页不能追加或结束新 busy。关闭、换窗口、
换目标及卸载结束原详情视图；后继从无旧游标的首读开始。
若失败结果的原输入已外置，展开后的恢复按钮使用这次取得的完整记录，不能继续
引用缺字段的预览。恢复只写草稿并保留重新附文件的要求，业务发送仍由用户显式发起。

待答问题在历史窗口外有独立入口，按原问题身份去重，不改变消息窗口成员。大
题干/选项加载完成前，提交按钮和 handler 均拒绝回答；全文只补题目内容，期限、
暂停和是否仍待答继续取当前 pending 状态。用户编辑后，原问题草稿保存已验证的
题干/选项与答案，关闭后的草稿恢复不会丢失上下文；它沿原草稿的接纳、丢弃和
账户寿命清理，不成为完整消息缓存。异步问题即使正文外置也保留可见问题提示。
问题暂停事件只投影身份、seq 和当前控制事实，移除其冗余题目副本，避免题目
大小使已经生效的暂停在浏览器中不可见；内部事件仍保留原内容。
历史/归档问题保留摘要作为预览，主动展开后读取原序列的完整只读记录，包含题目
header、选项标签和说明；不把已经关闭的问题恢复为可提交表单。

非持久 delta 没有详情引用。WS 文本块有界，浏览器 plain 缓冲最多 64 KiB。
JSON UTF-8 字节是预算单位。原生内容每项最多 16 KiB，集合最多 32 项、
合计 256 KiB，集合预算计入键和 runtime metadata。真实裁剪后记录截断，后续
纯文本追加通过原身份和顺序检查，推进原缓冲的到达标记，有需要时交付局部通知。
已裁剪的追加在展示值、身份和完整 metadata 均等价时跳过拼接、JSON 编码和
store 发布。真实 metadata 变化仍按现有预算更新展示。完整正文由持久消息恢复。
SocketDelivery 继续
保留256帧/1 MiB待发送总预算及原发送期限；连续积压可关闭慢连接，不阻塞业务
提交、原终态或内部完整内容消费者，重连不重新提交业务输入。

## 完成正文与同工作卡连续性

MessageBubble 将已完成文本的 Markdown 管线隔离在以实际 source 为输入的 memo
叶子，remark/rehype 插件数组保持稳定。当前流、后台流及 composer 编辑仍可
更新父卡控件与归属，未变正文不重新解析；真实正文变化、按需全文及重新挂载
正常计算。流式正文继续走 plain 路径。该边界不迁移草稿 File 的释放责任，不
缓存跨挂载全文或 AST，也不靠整个气泡的自定义比较器跳过交互更新。

原生工作身份使用经校验的 request、attempt、thread、turn，并限定当前 session。
同一挂载工作从 observed 到 saved、补齐 seq/detail_ref/cardId 或 inline 转 preview
时，列表 key、内部卡壳 key 与包装层位置保持连续；普通详情包装层一直存在，
预览控件只在需要时出现。资源变化仍按上节独立退休，不借稳定卡壳保留旧详情。
展开只归当前账户、session 和工作；身份不足时归实际 observed 引用或原 tool-call
范围，不按同名或复用 cardId 推断同工作，不跨实际卸载保存展开。保存消息、卡片
身份及快照决定已保存的正文与详情锚点。实时 item 的追加在其后按工作身份合并，
复用未变历史的投影。

`MessageBubble.rendering.test.tsx` 使用真实 Markdown 管线验证未变 source 的额外
解析为零和真实内容更新；`MessageBubble.continuity.test.tsx` 检查实际 DOM 与展开
连续性。两类详情测试覆盖首 render、旧 cleanup、迟到结果、窗口变化及重连前
旧按钮；QuestionPrompt 保留完整题目到达前拒绝提交的约束。浏览器详情、间距和
native-output 回归检查稳定包装后的实际布局及保存记录入口。

## 最新输出跟随与阅读意愿

ChatTranscript 的同次打开拥有临时跟随／阅读意愿，与“此刻几何上是否到底”和接触暂停
分开；真正离开再切回默认最新。同次消息窗口或实际节点更换保留原意愿和未结束
接触，只废弃旧方向、几何及位置工作；最后匹配的结束／取消才解除暂停。
同数量的流式 Footer、native 正文、已有卡片的被动增高及流转成持久行都能改变底部。
Footer 以 context 传入的会话 ID 订阅当前流，通过已提交的布局通知、列表高度回调和
实际 scroller 的 ResizeObserver 唤醒视口操作。当前视图由账户、session 和连续消息窗口确定；
同步 store 订阅退休离开的视图，A→B→A 不能使旧操作复活。当前位置操作与尾部
运动分别持有原视图和实际 viewport：用户阅读优先于初始/历史定位，定位优先于
尾部运动。写入前后与 cleanup 都复核自身仍当前，旧回调不能记入后继位置、
清掉后继或继续排帧。库的合法尺寸补偿仍保留。

尾部只有一个运动对象和一个待交付 frame，通过公开 scrollTo 写入。每次执行以
performance.now 计算真实 dt，从当下 scrollTop 追赶当下 scrollHeight−clientHeight；
tau 为60ms，单步至少1px且不超过当前 gap。后续增高更新这次运动的下一次采样，
消息仍即时发布，不增加消息队列。候选进入2px范围时请求底部，再以写后当前
几何判定完成；小数物理上限造成的≤2px残差停止，写中再增高超过容差则继续。
相等时钟读数不写、不推进时间原点，未完成目标保留唯一后续帧，无需新尺寸通知
唤醒；已完成则停止。关闭库内 followOutput，不并行运行原生 smooth。

上滚、定位或视图/节点退休立即取消运动。页面隐藏同步停止，不依赖后台帧交付；
零高测量也停止。恢复可见时按当前许可和真实几何重采样，以新时间原点开始，
不计入隐藏时长。聊天隐藏不按零尺寸重新判定意愿，原跟随者恢复追赶，原阅读者
仍保持阅读。同一会话切到管理页保留本次打开的呈现状态，切回沿当前视口恢复。
reduced motion 在同一当前性、取消及完成规则下直接请求当前底部，
不增加偏好订阅、计时器或第二套跟随器。

主动展开或收起转录内的工具、原生任务卡片、回复全文，以及待处理问题的详情
属于阅读操作。转录区域和历史窗口外的问题入口共用阅读捕获；在展开控件的
click 捕获阶段暂停跟随并取消在途 frame，先于子控件更新或原生
summary 默认动作；鼠标、键盘与辅助技术激活共用这一入口。按钮通过
`aria-expanded` 表达展开状态，原生 details 使用 summary。后续异步全文和流式
输出继续保留阅读位置；控件自身不重新开启跟随。主列表有效向下导航到底部可恢复，
收起导致内容缩短、浏览器把位置钳制到底部不算返回导航；原生 pointer 结束仍按
原手势证据判定。没有实际主列表向下移动的触摸／笔轻点，只可恢复手势前已有的
跟随许可，不能因当前恰好在底部而把暂停变为跟随。
已在底部时跳过多余的位置写入，不因一次布局通知重复滚动。

真实主列表向上滚轮、向上导航按键、原生滑块操作及触摸／笔的向上阅读手势及时
撤销跟随，默认输入行为继续交给浏览器。没有可向上滚动范围、缩放手势、表单
编辑及被内层输出消费或阻断链路的导航不误停主列表。单一接触记录只持本次
source、身份、位置及原许可。TouchEvent 接管完整触摸接触寿命后，旧 pointer
move/up/cancel 无权修改它；两种 identifier 不作相等假设。touchend/cancel 从
changedTouches 匹配所有者，多指失效后剩余一指不能重新认领。接触中的停留或
普通 scroll 不按超时恢复跟随。没有 TouchEvent 接管的平台保留 pointer fallback。
滑块按下先暂时挂起跟随；没有导航的松开恢复原许可，不由按住期间输出形成的间隙推断离开，
原历史阅读者也不因此恢复。原生滑块可能不交付 move，松开坐标仍参与识别移动；
活动接触期间的位置通知不能提前恢复许可，原生 panning 的 pointer cancel
不冒充回到底部。释放只交接本次已建立的有效向下证据和主列表实际位移；离手后
继续向下滚动可刷新500ms无进展界限，scrollend、反向、新输入、阅读及视图/节点
退休清理旧证据。触摸取消、内层滚动或未导航轻点不能借旧 wheel 证据恢复。

布局增高或缩小都可能改变 scrollTop，位置本身不推断用户离开。有效导航证据下
主列表实际向下回到距底部不超过4px 可恢复；已经在可信底部的明确下滚或有效 End
即使零位移也可恢复。表单编辑、缩放、内层消费、无效触摸和被阻断的滚动链路
仍不能授予许可。已经排队的“仍在底部”
事件不能撤销新上滚意愿。

主列表实际向上滚离底部后，正文左上角显示 Jump to latest。按钮叠在正文上方，
显隐时视口高度和阅读位置保持稳定。展开卡片、内层滚动和被动内容变化不触发。
滑块和滚动条轨道共用本次接触。滑块仍按住时，向下移动、范围变化或正文变更以当前位置重新取样，
后续向上位移仍可打开入口。按住期间不计算上翻确认的期限，松手后从释放时开始计算。
范围变化会退休其他尚未确认的输入。滚轮默认动作被取消后，
布局引起的位移也不会打开入口。同次打开保留入口，点击或手动回底恢复跟随后清除，换会话
重新判断。点击沿已有跟随动作到达含实时区的尾部，焦点交给正文。首次定位超时和读位失效
共用该入口。

尺寸通知本身不撤销意愿，持续输出和间隔输出适用同一规则。Home 由正文接纳后
暂停跟随，通过 Virtuoso 的公开滚动接口直达已加载历史的物理顶部。这样长窗口中
途量测的行高补偿不会截断跳转。写入后核对实际位移，后续布局与分页通知继续走原有入口。表单编辑和可消费
按键的内层滚动区仍掌握自己的输入。

历史加载先暂停跟随。用户继续阅读时，前插锚定及 DOM 校正优先完成。用户先回到底部
时，迟到的历史页仍正常合入，位置沿当前跟随目标更新。
`ChatView.motion.test.tsx` 覆盖60/120Hz、不规则/相等时钟、写中后继、末次增高、
小数钳制与停止；`chat-follow-output.spec.ts` 检查连续输出、阅读/回底、旧通知、
Footer 转持久行、原生触摸及隐藏/resize。验收看实际轨迹、间距和阅读偏移。

## 首次正文呈现

常规切换时，当前打开拥有正文的准备、揭示和交权，标题及适用的编辑控件先可用。
准备中的列表参与实际布局，正文隐藏并暂时退出交互。已安装的合法暖历史立即
参与定位，冷打开等待必要读取。可信空基线直接呈现空态。只有实时区或只有思考
提示时，按当前实际内容定位。暖刷新失败保留合法正文，必要历史缺失或损坏时
显示对应的错误与重读入口。

`react-virtuoso 4.18.6` 按 48 CSS px 估高并自然测量行。应用保留一个可取消的
initial，使用公开 `scrollTo` 到包含 Footer 的物理底部。实际列表和正文布局通知
共用一个待交付帧，位置写入后复核当前几何。揭示时距底部至多 1 px，应在首屏的
已提交持久尾行及实时末段实际可见。实时区独占首屏时，以已布局的列表空间和
当前 Footer 的真实末段为准。

揭示提交时再次校验当前正文和几何。揭示至首屏交权期间，迟到的 Footer 增高
仍由 initial 接纳。完成后由正常跟随处理新输出。首屏上翻或按住原生滚动条可
先接管，待交付的定位立即让位。归档交接的非空后继沿用同一可读条件。
[归档交接](frontend-list-reconciliation.md#会话列表与跨重连写入确认)

同次打开最多累计 2 秒有效前台准备时间。合法基线与正高度 viewport 同时存在
后计时，页面隐藏、零高和活动接触暂停计时。末行、输出和同次窗口或节点变化
共用原期限。可信基线定位超时后立即退休定位任务并开放正文，即便当时还没有
可读 DOM。开放沿原列表进行，无需新增 GET。优先用阅读锚点，缺少锚点时保留
可用的物理位置。独立状态区每次打开播报一次，只有被移除遮罩内的焦点交给
阅读区域。缺失或损坏的历史沿原错误与重新读取入口处理。重新读取仍返回同样
损坏的数据时，继续显示错误并保留拒旧水位。

该次打开仍可通过一次真正新接纳的非空流文本或新的生成正文恢复可见跟随。空文本、
旧重放、布局变化和快照不授予恢复。隐藏、零高和活动接触期间合并待恢复事实。
真实阅读导航撤销资格，原生滚动条接触结束时若仍可能有迟到导航，也撤销该次
尚未完成的自动回底。用户可用 Jump to latest 主动恢复。自动与主动恢复沿同一
可见跟随路径，只有真正的新选择会开始另一轮首次准备。

呈现回归覆盖真实末段、静止首屏、超高静态 Footer、首次可见后立刻上翻，以及
后续布局送达时的交权。 [暖切换](../../web/e2e/chat-presentation.spec.ts)
[输出跟随](../../web/e2e/chat-follow-output.spec.ts)

## 历史分页与阅读锚点

浏览器消息窗口供界面阅读。CLI 恢复使用独立的完整 typed 导出，固定成员、分页
校验和本地提交边界见 [Harness 导出合同](harness-layer.md#complete-typed-transcript-export-and-local-pull)。

聊天展示投影不为当前不显示的根 `thinking` 生成虚拟列表行；只让气泡返回
`null` 仍会留下列表项的 12px padding。原消息、内容与持久 seq 继续保留，
分页窗口和高水位仍按原始历史计算。原生 child 观察先归入其卡片，不因空思考
而消失。`nativeOutput.test.ts` 检查投影与历史分离；浏览器
`message-spacing.spec.ts` 比较重新加载前后的真实几何间距，覆盖连续七条空思考。

`observeOlderMessages` 持有原会话观察、请求寿命、窗口身份及旧页游标。store 在
一次更新内检验窗口和游标后接纳、排序、去重；替换后的窗口不接纳旧页，也不
让它的 has_more=false 关闭当前缺口。WS 尾部追加及保留同一连续范围的数组替换
保持窗口身份，不能无条件丢弃可用旧页。合并、过期、不需要、已有在途与失败
分别返回；取消只释放原读取的入口，迟到回调不能释放后继读取。

分页推进依据页面实际覆盖的范围，新增数只统计真正插入的行。重叠页可以新增
零行但仍合法推进游标；不能把已有行再 prepend 一次，也不能因零新增拒绝前进。
当前窗口和原 observation 已退休的页仍整页拒绝。页中已接纳的原 terminal／完整
native text 也执行同一身份清理，而不重放实时控制事件。

ChatTranscript 在有效 HTTP 响应合并前捕获当时第一个可见项的稳定身份和像素偏移，
请求等待期间允许继续浏览；用户导航退休过时定位，不因此废弃仍合法的页。
重组后按身份及实际 DOM 位置恢复，不再以总行数差补偿。每次实际位置写入都由
同一操作安排后续核验。锚点首次对齐后，再核对下一帧的列表高度和锚点偏移，
以纳入挂载范围变化后的虚拟尺寸补偿。目标离开挂载范围便释放旧的对齐测量，
重挂后按当前几何核验。仍有误差则继续校正，稳定对齐或物理钳制不再移动时
结算。导航继续退休位置操作而保留合法 HTTP 页。
目标未挂载时先用公开
scrollIntoView 探测行本身，再按 DOM 校准长行内偏移；calculateViewLocation 返回
null，避免启动库内延迟 index 重试。找不到目标、完成或取消只结算原操作。
同次打开跨窗口／节点交接优先保留未完成的原 key/offset；没有锚点也保留阅读意愿。
短寿命交接记录只保留可选锚点及旧节点／物理位置，消费、退休或卸载立即释放。
同窗读位暂时超出当前范围时，沿同一视口位置操作复核下一帧；若范围稳定，
在该范围内钳制并结算，在零范围结算到 0。旧位置因范围缩小而不再可达时，
偏移差不能证明原生导航。活动接触期间暂停恢复；有效的主列表导航可以退休旧读位。
换窗前的接触不能据此重新授予跟随许可。
原目标消失时，同节点保留或合法钳制旧物理位置；新节点无法恢复身份时采用已加载
内容起点，并提示原位置不可用。全文和后台任务不进入交接记录。
持久消息使用 seq，原生卡片使用原
工作身份，无 seq 的本地通知按消息实例保留弱引用身份；同文通知彼此独立。
这些标记不持久化，也不保存第二份 transcript。

阅读停在纯实时区时，根回复或 native item 同一次由流缓冲转成持久行。转存前捕获
当前文本的起点及偏移，匹配已提交的持久行后校正。新行的估值范围还未覆盖读位时，
通过 Virtuoso 的公开 `increaseViewportBy` 提前挂载新行，随定位结算释放。这个读位保证针对
转存前后排版一致的正文。等待旧页期间滚到纯实时区时，前插沿用库对现有列表的
几何补偿。 [转存回归](../../web/e2e/chat-follow-output.spec.ts)
[历史分页回归](../../web/e2e/history-pagination.spec.ts)

初始定位与[首次呈现](#首次正文呈现)归同一个 initial 操作。同 session 非空窗口替换废弃旧
位置证据，不假设 Virtuoso 必然重挂或重新执行 LAST，也不重置同次打开的阅读
意愿或已耗期限。初始结算、自动分页就绪和跟随意愿分别管理：挂载的假顶部不
自动读历史，取消、失败或空投影不封死手动 Load earlier messages/重试入口。

自动分页的 atTop/pagingReady 状态只唤醒请求入口复核：当前 viewport 必须正高度，
且当前物理顶部或首个已加载行的实际几何仍满足 atLoadedStart。旧顶部报告不能
在初始化已经到达数千像素外时请求历史并暂停跟随；隐藏视口也不能借旧报告读取。
应用恢复写入及与该写入匹配的滚动通知不发布到顶信号。同视图、同节点且位置不变时，
展开详情保留该写入标记。迟到的原生滚动若使带位置
保护的锚点校正或物理恢复失效，同一次通知仍可用于自动分页。发起读取即消费当次顶部信号；
前插后下一次真实到顶的通知可启动下一页。
手动入口保留原读取规则。失败/零新增停止原地自动重试，离开再回顶或手动重试
仍可继续；同窗切页保留原先资格和失败停顿。

切换会话、A→B→A、卸载/重挂或窗口更换都会结束原视图读取，旧回调不能修改
新视图的 loading、stalled 或锚点。同一窗口的连接/服务换代也会使读取失效；
原 UI read 仍负责结束自己的 spinner 并保留手动重试，发布资格由观察独立判断。
`transcript.test.ts` 与真实 ChatView 回归覆盖窗口缺口、交错和观察寿命；
`web/e2e/history-pagination.spec.ts` 经原 HTTP/WS、读取及 store，在实际浏览器

## 冷历史与运行成本边界

切会话首次可读、首次滚入未挂载长行、卸载重入和行内资源晚到分别观察。
正常冷加载可以等待；必要的首次解析不等于冗余。未变挂载正文的无关更新
不重新解析；运动结束、暂停或隐藏后停止应用排帧，退休节点释放视口 observer。

Footer 按目标会话订阅根流文本和 native item。历史投影消费该会话已保存的
历史、子卡和当前请求，按展示与操作字段保留等价行及顺序。输入区自行订阅草稿
文本，既有持久行只消费占用状态和恢复等实际操作权限。子卡、问题、权限、完整性
和分页有变化时照常更新对应消费者。跨会话的已提交草稿和附件仍按原请求及原
会话接纳回执。 [行渲染回归](../../web/src/components/ChatView.rendering.test.tsx)

字体、全文晚到与历史前插分别核验可见段落。图片晚到仍可能使段落漂移；
当前没有针对图片的固定预留空间或独立段落校正保证。输入到下一 rAF、实际
绘制和首次正文计算是不同指标，不把协议或断言耗时当作浏览器阻塞。
