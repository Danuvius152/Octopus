## Agent 表单实例

Agent 编辑草稿归一次打开实例。`openAgentForm` 每次递增临时打开编号，
`AgentFormPage` 用账户代次、打开编号和 Agent ID 为编辑组件设 key；对象切换、
关闭重开及同批次 A→B→A 都重新初始化草稿，旧实例不恢复资格。字段差异始终
相对本次打开值计算，其他客户端的 Agent 更新不把未编辑字段变成修改。
创建或编辑由本次打开的 Agent ID 决定，与当前 live 成员资格分开。外部归档后
仍编辑原 ID，硬删除后的保存也只会向原 ID 提交差异 PATCH 并保留其错误和草稿，
不会把原编辑稿改为创建另一个 Agent。归档行的成功保存不触发进入聊天的导航。

异步读取、失败回滚、错误和提交清理只写仍挂载且身份有效的原实例。保存回执
仍按原账户的 Agent 合并规则确认服务端效果；视图退休不撤销已提交写入。
只有原表单仍有效且处于编辑页签时，保存成功才选择 Agent 并离开表单，旧回执
不能关闭或解锁新草稿。

Save 在第一次 await 前同步取得本实例的保存资格，并冻结完整编辑区：文字、
模型/凭据、头像及弹层、工具/子代理配置和新的 Connector 操作均不得改稿或另写。
同步事件门禁覆盖 React 尚未渲染 disabled 的连续操作；保存期间晚到的安装偏好
也不能重写提交稿。已有 Connector 写入继续按原请求结算，不因 Save 被撤销。
Cancel、切页签及打开其他对象仍可用，离开只退休界面资格。

Connector 开关等待本次打开的绑定首读。读取失败时保持禁用，并可在原草稿重试。
首读发现该项已有待结算操作时，同项继续等待它结算。用户修改后，同项同步阻止
再次提交。明确拒绝或确认未发送时恢复上次确认值。写入结果未知时仍锁定该项，
用户点 `Check update` 后沿原操作结算，取得当前确认值再开放编辑。读取失败时保留
原操作 ID，可再次检查。其他项可以继续修改，Save 冻结整表。

读取、错误与结算回执只更新仍有效的原表单实例。退出结束读取及界面接纳资格。
服务端保留已提交的绑定，由[原绑定操作合同](connectors.md#agent-binding-writes)
裁定迟到写入和结算。

All 页签的 Chat 动作另有本次点击的前台资格。点击目标 Agent 与编辑对象分开；
离开原表单实例、对象、主视图或 All 页签时，同步订阅永久退休原资格，返回相同
值也不恢复。`openAgentChat` 先把原账户的成功交给 SessionList 确认，再检查
调用方前台资格决定导航；旧成功仍可进入共享列表，旧错误不能污染后来打开的
界面。订阅在资格退休或请求结束时释放，不增加全局前台状态。

## Connector 配置表单实例

ConnectorsPage 每次进入 setup 或 custom 都创建一个局部表单实例；Back、关闭、
页面卸载、对象切换和账户代次变化使原实例永久失效。同类型重开也重新初始化。
setup 的 kind、client ID、secret 和 redirect 来源同归本次打开；初始 GET 只补
未编辑的 client ID，用户清空也算编辑。secret 不从服务端回填；redirect 采用
本次 GET 的 URI，读取失败时保留本次打开的浏览器地址。

保存开始时捕获当前字段与原对象，实例内同步防止重复提交。成功回执仍可刷新
原账户的共享 catalog，但返回目录、错误和 busy 清理都须核验原实例，不能影响
另一草稿。setup 与 custom 共用弹层的 busy、错误和清理入口，两个保存入口遵循
同一实例规则。表单失效不会撤销已提交的配置，也不会自动重发保存；登录观察
继续由 `ConnectorOAuthOperation` 拥有，未并入表单状态。

## 应用修改草稿与视图寿命

`applicationDrafts` 按 App 保留修改文字的归属，以及构建、归档和 Retry deletion
的 busy/错误。等待期间文字仍可编辑，切换 App 或离开页面不移交这些状态。
构建操作始终由 `ApplicationList.build` 接纳实际结果；草稿清理使用原记录及稿版本，
不依赖包含连接资格的 `currentGuard()`，连接变化不会把已经确认的提交留作未发送稿。

提交时捕获稿版本，并立即让该版本退出可恢复未发送稿；文字暂留内存供检查。
成功回执只清仍属于原记录的同一版本，后续编辑即使文字相同也有新版本，不能被
旧回执清除。失败保留原 App 的内存文字及错误，结果未知不自动重发。忙碌和错误
不随页面刷新恢复；文本存储与账户规则归[输入恢复合同](input-reliability.md#browser-application-text-drafts)。

ApplicationView 的 App/账户视图寿命与 Iterate 弹层寿命分别控制关窗资格。
A→B→A、关闭后重开或卸载重挂均不能让旧回执关闭新弹层；普通成功仍会关闭
持续有效的原弹层。视图失效不丢弃原账户有效的列表结果，也不取消服务端构建。

`ApplicationList.onDeleted` 发布原账户已确认的 DELETE 和有效
`application_deleted` 事实，独立于该回执是否有资格直接应用列表行。草稿入口同步
移除原 App 的内存/存储并退休记录，旧 ACK、catch 和 finally 不能重新创建它。
未打开过的已存 App 同样清理；归档、列表暂缺或删除失败不证明删除，不清稿。
这里只退休当前记录，不增加永久删除标记或第二份应用列表。

旧构建会话删除后的现有 Iterate 初始化、
应用文件、错误和 Ready 含义保持原合同，不增加构建结果摘要或历史回填。

## 共享聊天文字与操作寿命

`textDrafts` 拥有账户内一份共享聊天文字、版本及同步保存错误；切换会话与
ChatView 卸载重挂不拆成每会话一份。`chatDraft` 接收已确认删除时捕获的
`wasActive`，在页面不在时也能清空当前会话的共享文字并推进版本。记录继续
有效，让仍挂载的输入框可以编辑下一稿；不使用永久墓碑或第二份会话列表。
存储与刷新恢复规则归[输入恢复合同](input-reliability.md#browser-text-drafts)。

ChatView 的 typing、history、slash、显式恢复、清空及两种发送均写入同一同步
文字入口。普通消息仍立即清空；原 submitted/rejected/unknown、恢复来源、附件
完整性及 message/compact 判断保持在原业务路径。compact 发出即让所属版本退出
刷新恢复，当前组件保留原 ID 的 GET 确认与内存命令；成功只清匹配稿版本，
卸载只清尚未被后续编辑替换的消费版本。不会将无原确认上下文的命令在重挂时
变回未发送稿，也不恢复旧操作资格或自动 POST。普通错误绑定账户、会话与原
操作实例，离开后即退休，返回同一会话也不恢复。共享稿、已提交附件与未知回执
由各自原所有者继续结算，后台只消费匹配的原提交快照。

fork 预填只持当前选择的记录、进入版本和是否已处理，寿命跟随共享 composer，
而非单次组件挂载。它等待 identity/metadata，保护已恢复文字与等待期间的编辑
或明确清空；先前会话的历史编辑不阻止新 fork 正常预填。账户退休后原记录
失效，旧回执不能清除新账户或相同字符的新版本。

历史遍历与按需全文由局部 `useComposerHistory` 共管，同步观察选择、账户和
共享稿的文字/版本；切会话不清共享稿，但永久结束旧遍历和读取。候选身份、
等待期间的同步发送准入及 Down 原稿恢复归[输入历史合同](composer-and-time.md#composer-history)。

## 前台键盘归属

聊天的全局 Escape 只在聊天主视图、当前选中 live 会话确实 running 时沿原
interrupt 路径生效。事件已被消费、原生 `isComposing` 或兼容 `keyCode === 229`
均在业务效果之前退出，隐藏但保持挂载的 ChatView 不获得停止资格。

共享 Popover 在自身冒泡阶段优先消费焦点所属面板或触发器的 Escape，document
监听只处理尚未消费的事件。两个面板由键盘打开而同时存在时，先注册的非焦点
面板不能抢走输入框的 Escape；外部焦点仍可关闭弹层，关闭不同时中断聊天。
Iterate 和侧栏新建会话的 Enter 也先复核原生输入法状态，再决定提交、清稿、
关闭或消费按键。输入法确认不构成业务提交。

## 账户表单与管理操作

改密的点击和 Enter 共用同步提交准入，输入法确认保留给编辑。旧账户的完成、
错误和清理只属于原表单操作。邀请和管理员列表分别保有读取状态及按行操作状态。
读取失败保留已取得的行，写成功后确认失败仍说明已写入和待确认的区别。丢回执后
可通过 GET 刷新列表，原写入仍未知，同目标维持操作占用，其他目标可独立操作。
已撤销、到期或使用次数耗尽的邀请不提供复制操作。

## 文件查看意图

已完成的聊天回复在正文和表格中把明确文件链接显示为可用键盘打开的行内按钮，
保留链接名称及可识别的位置。历史 Markdown 的路径按 URI 规则解码一次，普通
网页链接继续导航。链接、工具卡和归档会话的文件仍按各自原会话打开，查看器留在
当前前台。关闭时焦点回到仍存在的入口，入口消失时回到当前交互容器内合适的控件。

`/showme` 可直接输入路径、浏览文件或根据会话描述找文件。明确路径直接打开，
裸命令从当前可用来源进入选择器，支持切换来源、逐级浏览及按文件名筛选。明确路径
和选择器不新增聊天消息或启动模型。描述在查看器内单次查找，可显示候选或要求澄清，
详情见[描述查找与文件授权](multi-tenancy.md#viewer-file-access)。含空格的未引用文件名
先按字面路径查找，确认在授权来源内缺失时才提供按原文查找描述的操作。

查看意图绑定账户代次、原文件会话和前台。关窗、离开前台、切换账户或聊天会退役
整个查看意图，结束在途请求并释放面板和临时媒体资源。退出时把焦点还给仍存在的
原入口。文内文件引用、`+` 选文件和编辑路径都在同一查看器打开文件。

查看器同时容纳最多八个准备中或就绪的标签。不同标签保留各自的正文、阅读或源码
模式、滚动位置和源码分页。新文件准备期间继续显示原文。准备成功可保留标签，只有
仍拥有最新操作资格的候选才自动切换。打开文件、定位、PDF 翻页、媒体缩放、
显式切换和打开选择器会撤销此前候选的自动切换资格。取消会退役指定候选。打开失败关联具体目标，
仍存在的发起标签显示原因和重试，并保留原正文和焦点。关闭活动标签后优先选右侧最近的就绪标签，
然后选左侧。没有就绪标签时焦点转到文件选择控件。

聊天与查看器正文共用本地文件引用分类。相对图片和文件链接沿用原会话、所选来源及
已校验的父目录，来源内的 `..` 有效。绝对路径与本地 `file:` URI 经服务端确认，
网页和保留的站内路由继续导航。按来源和服务端确认的规范文件身份复用标签，通过
文档自身即可确认的标题、脚注和行号引用直接复用已读正文。

`+` 从活动标签已校验的来源及父目录打开选择器。父目录被替换时显示变化原因，取消
恢复 `+` 焦点和可用的阅读位置。关联标签随后台读取结算关闭时，选择器仍保留当前操作和目录。
打开和重载重新校验当前授权；重载始终提交到原标签，
成功替换快照，失败撤下旧正文并提供重试。重载期间仍可阅读及定位保留的旧快照，
路径编辑在新快照接替或显示失败后可用。切换标签可以继续读已有快照。路径可复制，
已确认的文件还可复制带来源和有效位置的 `/showme` 命令。授权与目录身份见[文件读取](multi-tenancy.md#viewer-file-access)。

路径编辑框用 `␛r` 显示回车，用 `␛␛` 显示字面 `␛`。剪贴板与文件请求使用
还原后的字面路径。普通文本拖放由浏览器处理。目标草稿或拖入文本涉及转义时，
编辑框在浏览器写入前提示改用粘贴，保留原草稿和原生编辑历史。
失败后编辑同一路径或仅修改位置，仍按当次读取已确认的来源检查访问权限。

查看器支持 `:12`、`#L12`、`#L12-L18` 和 Markdown 标题片段。带行号的
Markdown 文件先显示源码，阅读和源码可切换。位置在对应正文或源段就绪后定位，
位置失效时仍显示可读内容及说明。源码定位先切到目标所在源段。普通标题使用稳定的
Markdown slug，GFM 脚注和回跳使用其生成的 ID，面板隔离这些 ID 和辅助技术关联。

Markdown 正文默认 18px、行高 1.75、正文宽度上限 44rem，源码、纯文本和围栏代码
默认 16px、行高 1.6。正文与源码字号共有四档（16/14、18/16、20/18、22/20px）。
字号保存在本浏览器的账户键中，调整时保留当前可见段落或源行。窄屏将次要工具放在
有文字的菜单里，宽表和长代码可在各自区域滚动。图片沿用缩放，PDF 使用内置阅读器。

文本读取成功、图片解码成功、PDF 首页实际绘制成功分别标记预览就绪。PDF.js 阅读器
从准备到激活使用同一个 iframe，标签切回时保留页码和缩放。iframe 的 `load` 可能
先于 PDF 字节传输完成，内嵌原生阅读器也没有页面就绪回执。非活动面板和 iframe
退出键盘、指针和辅助技术交互。浏览器明确报告无内置 PDF 能力时，以说明、打开和
下载操作作为就绪界面。已指向文件的读取可从元数据阶段报告慢加载并提供重试，
重试替换原读取。`/showme` 解析期间可报告等候时间过长，用户可关闭查看器。该请求
由服务端识别路径和描述，确认文件前等待原查询结算。在正文、工具栏或标签栏重试
已确认的在途读取时，沿原来源和文件路径重新读取。共享读取的在途重试和失败后的原地
恢复均沿用最后一个仍有效且未结算的打开请求及其已解析的目标、描述和位置。共享读取失败时，
每个发起标签都收到该次读取中最近一个仍有效的打开请求的失败提示。只要首次打开仍有效，
文件标签也保留恢复入口。两种反馈均与元数据的返回顺序无关。任一入口重试同一次共享读取，
同源的规范文件就绪后，结算此前的恢复标签和发起标签上的对应提示。重试的身份确认晚于文件就绪时，
也按经授权的同文件身份结算关联提示。重复打开共享的文件时，最新选择负责定位和激活，读取仍保留
此前关联的失败。较新的失败独立保留，
仍允许通过授权的较早读取在后台就绪。
迟到的旧失败也不会恢复已结算的入口。每次打开各自保留已确认文件，别名改指后的读取单独结算。
关闭发起标签时，恢复标签的名称、错误、路径编辑和重试改用仍有效的打开请求。没有有效请求的恢复标签
会关闭，焦点回到可继续使用的标签或文件选择。较新打开可结算同一入口的旧失败，已提交的共享重试
复用校验仍按返回的文件身份决定是否打开独立文件。同一选择的文件就绪时结算更早的同文件确认，
即使发起标签还显示一次更晚打开的失败。已结算的确认不会重开用户关闭的文件。迟到的读取在目标
仍待确认时保留适用的慢读重试入口。同一别名确认到不同文件时，各独立读取按自己的进度
提供慢读重试和失败反馈，元数据的返回顺序不影响结果。较新的文件就绪可结算同一入口此前并入
共享读取且已被取代的普通选择。共享成员按当前读取确认的来源与规范文件身份识别。
重试保留的其他文件失败记录仍用于恢复。各次重试独立完成确认和读取。
新的打开在确认并结算前保留既有提示。显式重试并入共享读取后仍保留所属文件的失败反馈。
较新的文件读取失败按确认的文件身份结算较早的打开。较早的目标仍待确认时，按其最终确认的文件
判断旧错误是否已结算。可见的确认控件和失败提示共同按选择路径、确认路径、来源或尝试顺序区分，
未确认的目标也有单独提示。名称判重折叠空白，提示保留文件路径的原始空白。
显式路径命令重试成功就绪后，手动重载仍重新解析原命令，并保留后续的位置选择和明确清空的位置。
显式按会话描述搜索时，文件加载计时从取得候选元数据开始。后台重载重试保留所属标签的
新定位，也保留另一候选原有的自动切换资格。SVG 图片使用独立来源的 data URL。

PDF 阅读器读取字节和新标签页打开都使用 `preview=true`。服务端通过原认证、路径、
大小和类型检查后，仅 PDF 返回 `application/pdf` 与 inline。默认文件 URL 和下载
返回 attachment，并保留文件名、原字节、Range 与 ETag。Chromium 回归覆盖首屏绘制、
切换后恢复页码和缩放、关闭内置能力、原件下载，以及 SVG 的来源隔离。

## 账户注销

注销请求使用发起时捕获的 bearer。请求结算后，浏览器仅在 bearer 和账户代次仍
匹配时清理本地登录并刷新。当前登录在网络失败时也可退出。新登录和它的草稿不受
旧请求的成功或失败回执影响，即使重新使用同一 bearer。

## 聊天 reset 与延后 fork

[`useSessionFork`](../../web/src/hooks/useSessionFork.ts) 提供 queueFork、cancelFork、
reset 业务动作，拥有 reset 回执阻挡、唯一 fork watcher、每会话在途操作、重试和
清理。`sessionStore.pendingForks` 仍是唯一意图事实；hook 只保存原意图的引用及
临时 timer/请求状态，不建立第二个任务 store。ChatView 继续拥有输入提交、附件和滚动；
共享文字与保存由上述聊天稿入口负责。
Research 提交继续使用现有 `lib/research` 入口，不迁入通用聊天 controller。

每个 fork 请求捕获意图对象。旧 A 的成功、409、硬拒绝或网络错误均不能清除后来的
B，也不能把 A 的重试次数、退避或自动导航转给 B。只有仍拥有原意图的明确
`fork_blocked_parent_turn_active` 回执可以有限重试；其他失败不自动重放。成功创建
仍交给会话列表入口接纳，只有原前台观察持续有效且没有替换意图才自动切换。

reset 只处理开始时捕获的问题和 fork 意图；原观察有效期间阻挡延后 fork，回执或
观察结束时解除。账户、服务代次或组件观察结束后，旧回执不得向新范围写入展示。
视图或焦点离开后不再自动导航，但仍可在原账户/服务有效时接纳真实创建到会话列表；
离开后再返回也不会恢复旧导航资格。卸载注销订阅和 timer，已发 POST 的原意图按
引用退出，避免重挂后自动重放可能已接纳的请求；后来排队的另一意图保留。
旧操作的 finally 也只能删除它自己的登记，不能清掉新挂载创建的操作。
`ChatView.fork.test.tsx` 与 reset 回归覆盖这些交错。

## 会话模型设置实例

模型选择弹窗每次打开固定 session 初值及差异 PATCH 基线；账户、session 或
关闭重开创建新实例。外部 props／列表回流可更新当前设置展示，用户草稿和结果
未知的已提交字段依照[模型设置保存规则](model-reasoning.md#saving-defaults-and-repairing-an-existing-session)
留在原实例。成功回执先交给 SessionList 更新原账户事实，只有
原前台实例和观察仍有效才通知、关闭；旧 success/error/finally 均不能改新草稿、
错误或 busy。真实 ChatView 回归覆盖旧成功及失败穿过 store 回流、新保存已发出
与尚未发出的交错，不以组件卸载后的 setState 被忽略代替验收。

## 页面问题草稿与原回执

`sessionStore.questionDrafts` 按账户、session、request、attempt、question 保管页面
易失草稿，包括原表单和答案；切换会话、表单卸载和断线不丢弃。刷新页面没有持久
草稿保证。换账户/token 或确认删除会话会清理原草稿，迟到回执不能将它复活。

答案发送前，页面登记原 `client_command_id` 和不可变提交快照；迟到接纳只清该
快照，不抹去发送后的新编辑。unknown 时按原问题只读查询持久结算；旧结果缺少
命令关联、缺记录或查询失败都保留不确定性，不自动重答。
已关闭题目的草稿可由用户预览到空输入框，并显式发送为新消息；发送前登记原
continuation 的 `client_request_id`。该消息回执未知时查询原 submission，不能
生成另一身份重发。丢弃预览或切换会话后，旧预览标记不阻挡普通显式输入。

暂停只由有用户操作依据的 pointer、keydown、change 或 Tab/Shift+Tab 焦点进入
触发；程序 `.focus()` 和仅发送消息不触发。客户端发送原身份，Owner 唯一裁定。
暂停事件按原持久 seq 合并，旧 HTTP snapshot 不恢复已经清除的期限。

完成展示读取原 outcome，保留主状态、实际错误、输入恢复及唯一的记录缺口说明。
根 completed 但必要工具结果缺失时说明工具结果未确认，不另称缺少根终态；
已包含同一 canonical 原因的主说明不重复追加。执行失败与独立记录缺口同时存在
时两者均保留。工具自身的显式失败留在工具卡，历史缺少关闭原因时使用中性说明，
不猜测超时。

工具结果不再附加原生状态小字；聊天不再提供 Completion details 折叠块，也不
另显示“正文已保存”或恢复计数。原生状态、命令、恢复及 recording 字段仍按原
契约保存和解析，compact 原因与文件影响继续参与必要提示，浏览器不重新裁定
业务状态。结果正文、真实错误、图片预览/保存/复制以及既有任务卡操作保持可用。
